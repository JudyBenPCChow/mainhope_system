# 收款單據作廢 — 營運政策

介面用語：**繁體中文**。  
性質：**營運政策**（系統已強制禁硬刪；跟進報讀仍靠人手）。索引見 [`OPS_POLICIES.md`](OPS_POLICIES.md)。  
操作畫面怎麼按：見系統說明書 [`manual/PAYMENT_RECEIPTS.md`](manual/PAYMENT_RECEIPTS.md) §7。

---

## 1. 為何要作廢、不可刪除

- 已開出的繳費／收款單據屬**金錢與對帳憑證**，不可從系統直接刪除，以免無痕跡、難稽核。
- 單據開錯（金額、學生、項目、重複出單等）必須走 **「作廢」**：保留原單與操作紀錄，另開正確新單。
- 目的：保留完整操作記錄，降低款項被私自挪用或「刪單消帳」的風險。

---

## 2. 誰可作廢、如何確認

| 項目 | 規條 |
| --- | --- |
| 角色 | 僅 **admin（前台行政）** 與 **alien（外星人）**；專班老師無收款頁 |
| 確認 | 作廢時須再輸入**自己的登入密碼**，並填寫**作廢原因** |
| 學年 | 受學年編輯鎖限制（與其他繳費寫入相同） |

---

## 3. 系統會自動做什麼

| 項目 | 行為 |
| --- | --- |
| 單據 | 狀態改「作廢」；**單號保留、不重用** |
| 已付堂數／營收統計 | 不再計入該單（只認「已收款」） |
| 轉介回贈 | pending 會取消 |
| 月費帳期 | 對應 charge 回滾／作廢，以便可重開同月 |
| 收件匣 | **系統通知**給 admin／alien（老師看不到）；內文含跟進提示 |
| 電郵 | 僅原狀態為**已收款**時，通知指定管理層電郵（寄信失敗不阻斷作廢） |

---

## 4. 前台必須人手跟進（系統不做）

**作廢 ≠ 退班。** 報讀與收款是分開的；作廢後學生可能仍「就讀中」、點名紙仍有人，但對帳會顯示欠費／追收。

作廢成功後請立刻：

1. 決定該生是否仍應就讀 → 不應則**結束報讀**；應就讀則**另開正確新單**收款。  
2. 查看堂數對帳、繳費紀錄是否合理（學生列表已無「追收學費」標籤）。  
3. 若屬試堂轉正式一併收費：仍視為**正式報讀但該筆未付款**；僅家長不讀時才另退讀。  
4. 同批手足／同伴是否也要作廢或重開單。  
5. 告知家長：舊收據無效；以新單為準（單號不同）。

收到收件匣「單據已作廢」系統通知時，視同提醒完成上述檢查。

## 6. 系統現況摘要

- **已系統強制：** 禁硬刪、作廢須密碼與原因、audit、收件匣通知 admin／alien；已收款可另發電郵。  
- **尚未自動化：** 作廢後自動退讀／改試堂 outcome／改註冊狀態（有意保留；靠 §4 人手）。  
- **Resend 寄信：** 須已設定 API key／寄件網域；未設定時作廢仍成功，畫面／流程會提示通知未送出。
