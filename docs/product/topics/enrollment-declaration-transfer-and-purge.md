## 一句

到課義務跟報讀走；已繳堂數池跟人、年級、課程組走。手誤清除只刪報讀列，不結束該班宣告，舊班一旦整堂補回就會把人抄回去。目標是減少轉班、選錯班、按錯清除造成的錯誤宣告，而不是先人手清列。


## 目標

1. 同科轉班不要再靠「手誤清除＋另報一班」。
2. 真正的手誤報讀，清除後不應留下仍會被繼承、追收讀到的宣告。
3. 整堂補回不可把已轉走、已清除、已退讀生效的人抄回新堂。
4. 合法調堂生仍要能上補堂紙；不要用「抄宣告」充當上紙。
5. 不刪已繳堂數池、不改其他班宣告；手誤清除預設刪出席時，**已扣堂數不會退回**（見 §8.1 文案；§9 明寫不自動沖正）。


## 開工閘

## 1. 背景

2627 起正式點名紙是兩層交集：該堂有有效到課宣告，並且該生仍有該班報讀、通過報讀日與退讀日閘。試堂、以及請假補堂指向該堂的人，另外加入，不要求該班報讀。補堂生上紙只需要請假列的補堂排程，不需要宣告（`src/services/rosterEligibilityService.ts:70-78`）——三層表不要讓人以為宣告是上紙的必要條件。

已繳堂數池按「學生 × 學年 × 課程組別」（例如中四專科共用一口 S4 池）。報讀某一班只鑄／找到該組的池，並為該班排程建宣告。退讀一班應只結束該班未來義務，不刪池。

手誤清除（`purgeMistakenEnrollment`）的產品原意是：加錯人、選錯班，刪掉報讀與增退紀錄，「不留下任何痕跡」。生命週期孤兒題 O4 只處理出席（預設一併刪）。討論初期列出、尚未收窄的四項是：**宣告、池、待補堂、請假**。其後收窄時只收了宣告與池；**待補堂與請假須一併補回**（見 §8.1、D1）——刪報讀後 `student_pending_lessons.enrollment_id` 因 `ON DELETE SET NULL` 變空白、狀態可仍是「待補」；請假列亦不會隨清除結束。

前線實際用法往往是：**選錯組別或想轉班，先清除再報另一班**。同科改時段已有「轉時間」（退讀舊班＋新報讀＋作廢舊班未來宣告），但確認文案把清除寫成更乾淨的路，增退時間線也被刪掉。

未拍板前曾有方案「只作廢該班有效宣告」。對抗後知道不夠：點名紙本來就因沒有報讀而不顯示此人；作廢不能靠「讓他離開點名紙」成立。其後改從殘留例子收斂原則，並覆核程式與 production。專家覆核進一步指出：繼承日閘應閘在**補回日**（與名冊同源重鑄），不是原堂日；理由見 §7.1、§8.2。


## 2. 三層分別跟什麼走

| 層 | 跟 | 刪報讀時應怎樣 |
| --- | --- | --- |
| 報讀 | 這名學生、這一班 | 手誤清除刪列；退讀改狀態並留增退事件 |
| 到課宣告 | 這筆報讀的到課義務（**概念**；見下） | 該班義務應結束（作廢）；其他班不動 |
| 已繳堂數池 | 這名學生、這個年級、這個課程組 | 不刪；來源報讀可空白。刪出席時已扣堂數**不會**自動退回 |

**Schema 並無對應鍵。** `attendance_declarations` 表上**沒有 `enrollment_id`、也沒有 `class_id`**（`supabase/migrations/20260804010000_entitlement_pools_and_declarations.sql:57-71`），與報讀之間只靠 `pool_id` 間接相連，再經排程與報讀交集對上班。「到課宣告跟這筆報讀走」目前是概念，不是外鍵。任何要「按報讀找宣告」的實作都要留意這點。

點名紙看報讀 ∩ 有效宣告（補堂／調堂人口另靠請假列）。只刪報讀，正課紙會乾淨，義務列仍會被軟取消與改期繼承讀到。


## 3. 現行程式（2026-10-07 閱讀，未改）

### 3.1 手誤清除不結束到課義務

`purgeMistakenEnrollment`（`src/services/studentQueries.ts`）：

1. 重查該生該班出席，依確認刪除或保留。
2. 刪除該報讀的 `enrollment_change_events`、`student_enrollment_sessions`，再刪 `student_class_enrollments`。
3. 呼叫 `syncStudentEnrollmentState`。

不呼叫 `voidStudentDeclarationsOnClassFromDate`。確認文案寫「不留下任何痕跡」（學生詳情、班別詳情）。

**稽核：** 刪出席那條分支**會**寫 `mgmt_audit_log` 一列（`src/services/attendanceLifecycleQueries.ts:429-432`，`action: 刪除出席紀錄（生命週期）`，detail 含 `reason=purge_mistaken_enrollment`，並含學生 id、排程 id、出席日期、出席列 id）。張以諾／蔡曉朗殘留班**沒有出席**時，`hits.length === 0` 該 helper 直接 return（`:420`），所以根本沒寫——原稿以學生 id／姓名／報讀 id／池 id 搜尋得零列，**結論成立，成因是「沒有出席就沒有稽核列」**，不是「稽核不含識別碼」。報讀刪除本身**永遠不會**留下稽核列，即使有出席也一樣（那列記的是刪出席）。

出席確認沒有出席列就不再問。有出席時，清除預設刪出席；退讀預設保留。文案只講出席。寫入時只刪確認當下記下的出席 id；確認後新出現的列不會被刪。**例外：** 若確認的 id 全部已不存在、而仍有其他出席列，purge 會 **throw 並在四步刪除之前中止**（`src/services/studentQueries.ts:1842-1846`）——不是「清除仍會做完」。

**死碼：** `deleteEnrollment`（同檔 `:1805-1810`）硬刪報讀、不作廢宣告，且**全庫無呼叫者**。要刪掉或一併納入規則，不要留著等被接上（見 §9、D1）。

### 3.2 退讀會作廢，失敗不中止，且只從生效日起

`withdrawStudentFromClass` 更新報讀後呼叫 `voidStudentDeclarationsOnClassFromDate`。失敗只 `console.error`（`:1948-1956`），退讀仍算完成。

該函式只處理 `scheduled_date >= fromDate`、狀態不含「取消」的排程，只把 `active` 改 `void`。不改池餘額。

**阻塞級：** 方案若把前線推去用退讀／轉時間，卻只修手誤清除、留著退讀 best-effort，等於推薦路徑比被勸退的路徑更不安全。退讀作廢失敗應對稱納入（見 §8.3、D7）。

### 3.3 池不隨報讀刪掉

`student_entitlement_pools.source_enrollment_id` 可空，外鍵 `ON DELETE SET NULL`。專科共用鍵是年級碼（例如 `S4`），不是班別。

管理端單列刪出席（`deleteAttendanceDetailAsMgmt` → `deleteAttendanceHitsWithAuditOrThrow`）**不回沖**堂數。`entitlement_reinstated` 全庫只在 `applyEntitlementConsumptionDelta` 寫（`src/services/entitlementQueries.ts:1240`），呼叫者只有點名儲存／roll-call 路徑。因此手誤清除預設刪出席 → **池餘額仍被扣過**；「已繳堂數池不動」若寫成餘額不變，是半真（見 §8.1）。

### 3.4 正式點名紙

`rosterStudentsFromDeclarations`、`rosterStudentsForSchedule`、`fetchRosterForRollCall`、`fetchClassStudents`：宣告路徑都要求該班仍有報讀且通過日閘。試堂與請假補堂另外加入。

RPC `get_teacher_schedule_roster_context` 只載入狀態「就讀中」的報讀。已退讀的人即使宣告仍在，正課紙也沒有他。日閘 helper `enrollmentPassesDateGates`（`src/services/scheduleRosterQueries.ts:405-421`）閘的是傳入那筆 `schedule.scheduledDate`——即**那一堂的日期**（補回場景＝補回日）。

### 3.5 改期補回會把已作廢的宣告抄回新堂

`inheritDeclarationsAcrossSchedules` 讀原堂 `active` 與 `void`，同一學生同一原堂優先 `active`，否則最新 `void`，在新堂插入 `active`。不檢查該生是否仍有該班報讀。來源改為 `class_reschedule`。

全班補回加堂（`scheduleMakeupQueries.ts`）在寫入 `makeup_of=` 後呼叫此函式。軟取消則 `voidActiveDeclarationsForSchedules`，不過濾報讀、不改池。

同一堂同一學生只容許一筆 `active`。`ensureEntitlementPoolAndDeclarations` 遇到衝突會略過插入。衝突偵測用**錯誤訊息字串比對**（`includes("attendance_declarations_active_schedule_student")`），不是 error code。繼承回傳筆數是 `toInsert.length`，不是實際插入數。

除繼承外，沒有第二條「讀 `void` 再插入 `active`」的路。其他插入是：報讀鑄造、單堂改掛、加堂挑選、請假調堂（新建，不是抄 `void`）。

**預覽 ≠ 實際繼承（已核實）。** 預覽「原應出席」（`scheduleMakeupQueries.ts:162-191`）讀 active ∩ 就讀中 ∩ 日閘，加試堂與補堂生、減當日請假；實際繼承（`entitlementQueries.ts:930-931`）讀 active **或** void 全部，無報讀、無日閘、無試堂／補堂過濾。兩者是完全不同的查詢。方案稿「預覽應與實際一致」是**新增需求**，不是現況描述。

**整堂補回同樣不是交易（已核實）。** 順序：新排程寫入（帶 `makeup_of=`）→ 作廢來源 active → 批次插入新宣告，全程無交易。中途失敗留下：新排程在、來源 active 已被作廢、新宣告只插一半；重試會被 `findExistingMakeupScheduleIds` 擋住。見 D9。

**表上沒有 void 原因可用。** 沒有 `void_reason`／`voided_at`／`voided_by`；`manual_reason` 這個欄存在但**全庫從未寫入**（只有 SELECT）。繼承目前只能分辨 `active`／`void`／`superseded` 與 `source_event_type`。

### 3.6 學費追收

專科以有效宣告為準。就讀班上的 `enrollment_auto` 計入；退讀班殘留的 `enrollment_auto` **不計**。`student_makeup`／`class_reschedule` 落在別班、但同一已繳堂數組別，**仍計**（`CROSS_CLASS_CHASE_DECLARATION_SOURCES`，`src/lib/tuitionChaseDetail.ts:12-15`）。因此繼承一旦把殘留抄成 `class_reschedule`，追收會多計堂。重鑄若改 `source_event_type`，會牽動此口徑（見 D10）。

### 3.7 轉時間

同科同學年專科：先退讀舊班（生效日在程式裡是**今天**，`transferClassTimeQueries.ts` 傳 `localTodayYmd()`），再為新班 `insertEnrollment`。舊班未來宣告會作廢。請假與補堂跟舊班，不搬去新班。

報讀衝突只擋同一班重複就讀、以及時段撞堂，**不擋同科兩班**。

### 3.8 阻塞級實作缺口（方案原稿未提）

1. **功輔月費 `ON DELETE RESTRICT`＋無班種守衛。** `homework_tutoring_monthly_charges.enrollment_id` 是 `ON DELETE RESTRICT`（`supabase/migrations/20260824184500_homework_tutoring_product.sql:105`）。手誤清除刪除順序是出席 → 增退事件 → 選堂 → 報讀（報讀最後）。按鈕在班別名冊列上**沒有班種守衛**（`src/components/classes/ClassDetailView.tsx:2532-2534`，就在「退讀」旁邊）。後果：該生有功輔月費列時按手誤清除 → 出席已刪、稽核已寫 → 刪報讀 FK 失敗 → **留下「出席已刪、報讀還在」的半途狀態**。若照 §8.1「先作廢再刪」，失敗後正是 §7.4 自己點出的形狀（宣告已作廢、報讀仍在、狀態仍就讀中）。原稿 §5 寫「專科這條用不上」對張以諾／蔡曉朗成立，對「按鈕沒有班種守衛」**不成立**。
2. **學年鎖是第二條失敗向量。** 同一 helper 內 `assertAcademicYearEditableForDate`（`attendanceLifecycleQueries.ts:435`）在刪出席迴圈中逐筆檢查——出席跨已鎖學年時會刪到一半才 throw。
3. **實作方式：** 交易或補償式回滾；repo 內已有先例可抄：`insertEnrollment` 的 catch（`studentQueries.ts:1638,1654`）。或走單一 RPC。見 D1、D9。


## 4. 觸發例子（production）

### 4.1 張以諾（`20261908`）— 同科轉班卻走清除

現有報讀只有中文 A（`2627-CHIS4001-A`），就讀中，報讀日起 2026-09-12。沒有中文 B 報讀，也沒有中文 B 增退事件。

| 班 | 宣告 | 筆數 | 排程日 |
| --- | --- | --- | --- |
| 中文 A | `enrollment_auto`／active | 39 | 2026-09-12 至 2027-06-26 |
| 中文 B | `enrollment_auto`／active | 39 | 2026-09-06 至 2027-06-27 |
| 中文 B | `enrollment_auto`／void | 1 | 2026-09-20 |

B 班那筆 void 與排程 `9e01ed21-…` 同秒更新（2026-10-06 16:54:35 UTC），原因老師請假。其餘 39 筆 B 班宣告仍有效。B 班沒有他的出席。

S4 專科池與 B 班宣告同一秒建立，`class_id` 仍是 B，`source_enrollment_id` 空白，尚餘 1 堂。其後 A 班宣告寫進同一口池。A 班兩次現場扣的是這口池。稽核表以學生 id／姓名／報讀 id／池 id 搜尋，零列（成因見 §3.1：殘留班無出席）。

形狀與手誤清除相符：先報 B、再報 A、B 的報讀後來被刪。不能證明當天按的是這個按鈕，還是有人直接刪報讀列。

### 4.2 蔡曉朗（`20261812`）— 中文報讀消失，宣告仍在

現有報讀：中四數學 A、暑期數學 B。沒有中文報讀，也沒有中文增退事件。

中文 A：40 筆 `enrollment_auto`／active（2026-09-05 至 2027-06-26）。沒有該班出席、請假或待補堂。與數學 A 宣告指向同一口 S4 池；池 `class_id` 是數學 A，來源報讀空白。扣堂都在數學班次。沒有中文繳費單（繳費明細沒有 `enrollment_id`，張以諾的收據寫的也是中文 A 不是 B）。

### 4.3 蔡曉朗中三 — 掛錯補堂班，再被整堂補回抄走

這筆不是「中文被清掉」的同一形狀，但是同一個學生身上、繼承會抄 `void` 的實例。

| 時間 (UTC) | 庫內結果 |
| --- | --- |
| 2026-09-06 02:49 | 中三數學 A、9 月 12 日：`student_makeup` 宣告。`source_event_id` 是他**中四數學 A** 9 月 5 日請假 |
| 02:50 | 該中三堂因導師請假取消，宣告被 void |
| 03:05 | 補回 9 月 10 日；`class_reschedule`／active；備註 `makeup_of=` 指向 9 月 12 日原堂 |

請假現況：已完成；補堂日 9 月 7 日，掛中四數學 B；現場出席也在 B。他沒有中三數學報讀。9 月 10 日這筆應定性為**錯誤抄回**，不是當日補回的預期結果。沒有當日操作原文，但庫內形狀足夠這樣定性。在 D2 新規則（補回日名冊）下的定性**尚未另核**（見 §12）。

其後請假改掛 9 月 7 日時，程式只作廢「上一筆補堂排程 id」（9 月 12 日），不會清繼承出來的 9 月 10 日。

## 7. 初稿方案的模擬：會出現的新問題

初稿兩句是：手誤清除必須作廢該班宣告；繼承時若此刻沒有該班就讀中報讀、且不是有效補堂請假，就不要抄。模擬後這兩句太粗。其後草案曾改成「問原堂當日是否應在紙上」；專家覆核指出日閘應閘在**補回日**（見下）。

### 7.1 繼承不要用「此刻就讀中」，也不要用「原堂日」

只問現在是否就讀中，會：

- **誤抄。** 蔡汶軒中文 A 退讀生效日已是 2026-10-04，列狀態仍是就讀中，同時已報中文 B。只看就讀中，A 班其後整堂補回仍會抄他。點名紙有日閘，人不上紙；追收把就讀中的班都算進去，抄成 `class_reschedule` 就多計堂。
- **重報同一班後誤抄。** 清除後又重新報該班：舊 `void` 仍在。只看今天就讀中，整堂補回一堂「入讀前已取消的舊堂」，會把舊義務抄到新補回日。

曾改寫成「問**原堂當日**是否應在紙上」。這仍錯，三條獨立理由：

1. **§7.1 自己給的「人不上紙」理由，紙的日閘閘在那一堂（補回日）。** 用原堂日，蔡汶軒只要原堂日早於退讀生效日，照樣被抄——與「紙帳分離」直接相反。
2. **已拍板的 `roster_policy=class_all` 就是補回日讀法。** [`nonstandard-scheduling.md`](./nonstandard-scheduling.md) 定明：取消後以「安排補堂」建立的補回堂＝不可剔人、全體就讀生上紙、固定 `class_all`（約 §206-207）。紙上的人是**當下就讀生**。「會上紙的人」＝「補回日閘通過的人」。用原堂日會做出「紙上沒有他、帳上有他」。對齊 M05（[`makeup-special-cases.md`](./makeup-special-cases.md)），**引用、不重開**。
3. **原堂日的狀態在資料模型上算不出來；補回日算得出來。** `insertEnrollment` 重報會改寫同一行（覆寫 `enroll_date`、清退讀欄）；手誤清除硬刪報讀與增退事件；名冊 RPC 只回就讀中。要實作原堂日得另寫一套，離開現有 `enrollmentPassesDateGates` 語意。

正確是問：**補回日**是否應在紙上（與名冊同源），不是問今天，也不是問原堂日。能分辨「原堂日 vs 補回日」的，只有「原堂當日仍在讀、補回日已轉走」的形狀（例如蔡汶軒）；張以諾／蔡曉朗／林藝涵三種讀法都跳過（林藝涵兩日都在退讀之後）。

請假例外：只有**已改掛到新堂**的未完成請假才納入（該分支以 D3 為前提）。已完成請假、退讀生效日當日及之後、已清除而無報讀覆蓋補回日的，都不抄。

### 7.2 調堂生：不要用抄宣告來補紙

點名紙上的補堂生靠請假列的補堂排程，不靠宣告。現行整堂補回**不會**改掛這條請假。

- 只跳過無報讀、不改請假：調堂生本來就不在新紙上，紙沒有更差。
- 因為請假指向原堂就抄宣告：人還是不上新紙（沒有該班報讀），卻多一筆 `class_reschedule`，追收多計。這是新問題。

因此 §8.2 請假分支與 D3 **綁死**：若 D2 同意、D3 不同意，不可保留「請假指向原堂就抄」——否則會把 §7.2 剛指出的 bug 原樣放回。

若要整堂補回連調堂生一起帶走，必須**一併改掛請假的補堂排程**。改掛之後，現有 `syncStudentMakeupDeclaration` 會跟；繼承不要再為調堂生抄一筆。改掛之後，改期或清調堂才作廢得到正確的那一堂。本案也觸及 [`makeup-special-cases.md`](./makeup-special-cases.md) **Y06**（待補期間退讀、轉班；狀態仍**待確認**）——應標成**輸入**，不假裝已關。

### 7.3 把人趕到轉時間、不改生效日，會出現空窗

現行轉時間：舊班退讀生效日是**今天**，新班第一堂可以是之後的排程。9 月 6 日轉去中文 A、第一堂 9 月 12 日，會造成中間一週兩邊都不上紙。

手誤清除再另報，反而能暫時留住舊班——這也是前線走錯路的原因。只禁止同科兩班、不修正退讀生效日，會逼出空窗。

蔡汶軒說明過渡是真實需求：中文 A 退讀生效 10 月 4 日、中文 B 由 10 月 4 日起報，兩班狀態都仍是就讀中。禁止「同科同時就讀中」會擋這種過渡。10 月 4 日已過、A 仍是就讀中，是現有缺陷；方案會放大它。

### 7.4 手誤清除「失敗則中止」的寫入順序

先作廢再刪報讀：若刪報讀失敗，宣告已作廢、報讀仍在，人從點名紙消失但狀態仍是就讀中。

先刪再作廢：若作廢失敗，回到現況（沒有報讀、宣告仍有效）。

兩步不是同一筆資料庫交易。要失敗中止，就要能回滾，或走單一後端程序。§3.8 指出功輔 `RESTRICT`＋無班種守衛＝**現成觸發器**，不是假設情境。

作廢有效宣告**擋不住繼承**（現行繼承也讀 `void`；改為重鑄後則以補回日名冊為準）。作廢仍值得做（收款建議、重報同一班時的唯一索引、清理標記），但不能替代繼承規則。清除時應作廢該班全部有效宣告（含已取消堂上尚未作廢的），不是只作廢未來堂。

**保留出席 vs 作廢該堂宣告（已拍板，改寫）：** 產品定案為——**手誤清除只限該生在該班完全沒有出席**。若有任何出席，不算手誤，系統應擋住清除，改走退讀或轉時間／轉班。因此不再提供「保留出席並清除報讀」；也不再問「保留出席時宣告留不留」。現行確認對話若仍有「保留出席」選項，實作時須拿掉或改為導向退讀。

### 7.5 作廢蓋原因：稽核用，不能取代日閘

在作廢當下蓋原因（退讀／清除／堂取消）值得做：那時上下文都在；手誤清除會刪掉歷史，重報會改寫同一行。清理與稽核也需要標記。可加 `void_reason`，或開始寫既有的 `manual_reason`。

**對林藝涵這類「先轉走、再取消／補回」：** 若離開時已蓋「人走了」，補回若只抽「堂取消」標記，可不抄她——**單靠分開標記即可蓋她這條時間線**。  
**對「先取消、再轉走」：** 作廢當下仍是「堂取消」，原因不會自動變；單靠標記不夠。已拍板用 **D4 選堂表單**（含已約補回堂）寫準退讀生效日，並在退讀時把相關宣告改成「人走了」；主繼承仍以 **補回日名冊重鑄（D2）** 為準。

**但不能單獨當繼承規則。** 軟取消會先蓋「堂取消」；學生其後才退讀時，若只看舊原因仍可能抄回。原因是**作廢當時**的快照。

正確分工：**補回日名冊為準**（§8.2）；原因欄作**稽核**、輔助跳過「清除／退讀作廢」的 void，並配合 D4 在退讀時改寫。見 D8。

### 7.6 模擬後不會變成新問題的

正課紙不會突然多出幽靈學生。張以諾這類殘留，繼承若按補回日名冊會跳過。單堂改掛仍有報讀。加堂挑選只從來就讀生。池不刪、其他班宣告不動；已扣堂數不自動沖正。暫不清現有殘留不會多出新列。


## 8. 收窄後方案（D1–D9 已拍板；D10／D11 待填）

### 8.1 手誤清除

**前置條件（已拍板）：** 該生在該班**完全沒有出席**才允許手誤清除。若有任何出席，擋住清除，提示改用退讀或轉時間／轉班。

刪報讀前，作廢該生該班所有有效宣告。作廢與刪除要能一齊成功或一齊回滾（交易或補償式回滾；處理功輔 `RESTRICT` 與學年鎖，見 §3.8）。池不刪；其他班宣告不動。

確認文案改為：會刪報讀與增退紀錄；該班到課宣告會作廢；**已扣堂數不會退回**（若過去曾扣過；本題清除路徑因無出席，通常無當堂扣數，但仍勿寫「池餘額與清除前一樣」）。不要再寫「不留下任何痕跡」。拿掉「保留出席並清除」選項。

**待補堂與請假一併處理：** 刪報讀後待補堂列 `enrollment_id` 變空白、狀態可仍「待補」；請假亦不隨清除結束。文案與寫入須交代後果（結束／改狀態／提示）。

按鈕保留，留給：報錯人、報錯年級、根本不該有這筆報讀（且尚無出席）。不要廢掉。`deleteEnrollment` 死碼：刪掉或納入同一規則（見 §9）。

### 8.2 整堂補回繼承

**日閘閘在補回日，不是原堂日。** 只抄／重鑄「**補回日**當日應在紙上」的人：

- 該生在**補回日**通過報讀／退讀日閘（與名冊同一支函式，例如 `rosterStudentsForSchedule`／`rosterEligibilityService.ts:52-54`）；或
- 有**未完成**請假，且補堂排程**已改掛到新堂**（此分支**以 D3 為前提**；若產品 D3 不同意，此分支不得保留）

已完成請假、退讀生效日當日及之後、已清除而無報讀覆蓋補回日的，都不納入。

**實作改為按補回日名冊重鑄（re-mint），不要「過濾舊 `void` 再抄」。** 取池可按年級課程組取得（`fetchPoolByNamespace`），不必經 void 列；衝突走既有 `insertActiveDeclarationsIgnoringConflicts`。預覽／會上紙／會鑄三者同源——「預覽應與實際一致」是**新增需求**（現行預覽與繼承是兩條不同查詢，見 §3.5）。

調堂生要上新紙：改掛請假的補堂排程（D3），不要靠抄宣告充當上紙；改掛後由請假路徑建宣告，繼承不要再抄。

引用（**不重開**）：[`nonstandard-scheduling.md`](./nonstandard-scheduling.md) 的 `class_all`；[`makeup-special-cases.md`](./makeup-special-cases.md) M05。重鑄的 `source_event_type` 與混級 legacy 池取序見 D10、D11。

### 8.3 轉時間與退讀生效堂（已拍板）

同科同學年專科：報讀第二班時應引導「轉時間」，而不是先清舊班。不要在退讀生效日改好之前，硬禁止同科兩班就讀中。

**退讀／轉時間必選「從哪一堂起不上」（已拍板）：**

- **真源是排程列**，不是手填「第 N 堂」序號。
- 清單每一列展示 **第 N 期・第 N 堂・日期**（無期數結構的班型可只顯示日期／用途）；**已約的補回堂**必須可選，並標明「補回（對應第 N 期第 N 堂／原堂日）」。
- **語意定死：**「**從這一堂起不上**」（含該堂）→ 退讀生效日＝該堂 `scheduled_date`。
- 到期要把舊班真正改成已退讀；作廢該生效日起之宣告，並蓋原因「人走了」（D8）；若該列先前因堂取消已是 void，退讀時**改寫**原因為人走了。
- **補回尚未安排時：** 清單沒有補回格可選。預設：若選的是已取消的原堂（或生效日落在該取消日），則**其後任何對應補回亦不上紙**（名冊日閘／重鑄會排除）。勿強迫行政先約補回才能退讀。

**重開範圍：** 取代關帳後落地行為「舊班退讀生效日固定為操作當日」（`transferClassTimeQueries.ts` 傳 `localTodayYmd()`）。須對照 [`transfer-class-time.md`](./transfer-class-time.md) **產品規則第 4 條**（已約在新班尚未上的補堂：報讀第一堂必須晚於該日）及「一句」請假／補堂跟舊班；同步 2627 營運指引 §5.4 與行政 playbook。D3 另觸及「一句」與 Y06（輸入、不假裝已關）。

**退讀對稱：** 宣告作廢失敗改為中止／重試（D7）。

轉科：退讀舊班再新增報讀，不要用手誤清除。

**分批補回（人人不能同一日）：** 本次**不納入**；維持 M05 全班同一日不可剔人。不能來者另建請假／調堂。

### 8.4 現有殘留

規則落地後，用**墓碑條件**一次處理 §4–§5 的列，不要人手改，也不要把「繼承時抄誰」直接拿來清庫。

**墓碑條件（與繼承條件分開）：** active 的 `enrollment_auto`，而該堂日沒有報讀覆蓋 → 作廢。這與 §8.2「補回日名冊重鑄誰」是**兩條不同條件**。

清理流程建議：dry-run 清單 → 逐列分類 → 寫稽核 → 清理 → 追收與點名紙前後對照。林藝涵 10 月 4 日、蔡曉朗中三 9 月 10 日一併納入。

**尚未核實：** 這批殘留之中有沒有任何一列旁邊掛著計費出席——決定能否直接作廢。

- 不留 `deleteEnrollment` 死碼等被接上：拍板後刪掉，或納入與手誤清除同一套作廢規則。


## 10. 建議實作順序（拍板後）

依專家覆核收斂的九步（施工項；未拍板前不開工）：

1. **蓋原因**：作廢時寫 `void_reason`（或開始寫 `manual_reason`：退讀／清除）；原因欄作稽核與跳過清除／退讀 void，**不取代**補回日名冊（D8）。
2. **繼承**：按**補回日名冊重鑄**（與名冊同源，不過濾舊 `void`）＋未完成且**已改掛**的請假（D2；請假分支以 D3 為前提）；單測含林藝涵／張以諾／調堂生／預約退讀；釘 D10／D11。
3. **手誤清除**：作廢該班全部有效宣告，與刪報讀**同一交易**（或補償回滾）；改文案（已扣堂數不會退回）；補報讀層稽核；處理功輔 `RESTRICT`／班種守衛／學年鎖；待補堂與請假（D1）。
4. **退讀**：作廢失敗改為中止或重試（與第 3 步對稱；D7）。
5. **整堂補回**：交易化；補堂排程改掛（若 D3 同意）；預覽與複製／重鑄同源（D9；**不擋** D1／D2 拍板）。
6. **轉時間／退讀：** 必選「從哪一堂起不上」的排程列（畫面標第 N 期・第 N 堂・日期，含已約補回）；生效日＝該堂日；未約補回則選取消堂即含其後補回不上紙；到期改已退讀；改寫相關 void 原因為人走了（D4）。
7. **引導**：同科已有就讀中專科時，新增報讀提示改用轉時間（不要先硬擋；D5）。
8. **清理** §4–§5 殘留：dry-run → 逐列分類 → 稽核 → 清理 → 追收與點名紙前後對照（D6；墓碑條件 ≠ 繼承條件）。
9. **文件同步**：**引用並對齊** M05／`nonstandard-scheduling.md` 的 `class_all`（**不重開**）；Y06 標成**輸入**；標明 D4 重開範圍；同步 2627 營運指引 §5.4 與行政 playbook。
