## 5. 討論／對庫筆記（2026-08-31）

### 5.1 C1「共用 `classes`、唔另開三套表」

而家專科／私人／功輔已經喺**同一張** `classes`，用 `class_kind`（`group`／`private`／`homework`）分流。報讀、排程、收款、點名都 FK 去呢張表嘅 `id`。

Production 欄位（2026-08-31）分組：

| 組 | 欄位 | 私人實際 |
| --- | --- | --- |
| 識別 | `id`、`class_kind`、`subject` | 三樣都有；班名＝學生＋科＋一對一／二 |
| 專科目錄 | `course_id`、`section_code`、`course_code_full`、`grade`、`day_of_week`、`time_slot`、`lesson_slots_per_session` | 全空（無模板、無逢星期） |
| 人／房 | `teacher_id`、`classroom_id`、`capacity` | 有老師；課室空（約堂先指定） |
| 價錢 | `price_per_lesson` | 可有 |
| 學年窗 | `academic_year_id`、`academic_year_label`、`start_date`、`end_date` | 而家誤填 2526／6-30；C3 要改空 |
| 狀態 | `status`、`enrollment_notice` | 進行中 |
| 系統 | `created_at`、`updated_at` | — |

「唔另開三套表」＝唔建 `private_classes`／`homework_classes`。規則可以三套，儲存共用；用唔到嘅欄位留空。

另建表好處：各線欄位可強制（私人禁學年、專科必填學年＋編碼）；少「可空欄位」。壞處：報讀／排程／收款／點名／請假／計糧全部要拆 FK 或 UNION；9 班私人＋1 班功輔 vs 幾十班專科，維護成本遠高過可空欄位。C8 清私人學年＝清空呢欄，唔刪 column。

**清空學年會唔會爆？** 欄位本來可空；排程／收款／點名跟 `class_id` 同日期，唔跟班學年。唔會因為「沒有學年」而 insert 失敗。會出事嘅係**推斷同篩選**：

| 行為 | 清空後 |
| --- | --- |
| 點名紙（現有 9 班） | `usesEntitlementRosterModel(空)`＝舊路徑；有報讀就上紙。**唔會空白** |
| 鑄權益池 | 班無學年 → 唔鑄池（程式直接 return）。C6 本來就唔用池擋紙 |
| 班別／請假／試堂列表 | 軟封存**刻意保留**學年空白嘅班，唔會消失 |
| 人數報表揀 2627 | 會漏私人（C15） |
| 畫面顯示學年 | 若連 `academic_year_label`／`start_date` 都空，有啲 UI 會用**今日**推成 2627。開工時要一併停呢種推斷，並清 label |
| 今日開新私人班 | 未改 `createPrivateTutoringEnrollment` 前仍會自動蓋 `is_current`（所以先停寫年，先清舊班） |

結論：清空唔會令系統當錯誤擲出；要先改「無年就當今年」同人數報表，否則顯示會誤導。專科／功輔繼續必填學年，唔受影響。

### 5.2 C8 私人要唔要去除學年欄位？（建議）

**要：私人班唔用 `academic_year_id`。唔刪欄位。**

`classes.academic_year_id` 而家可空；專科同功輔仍然**必須**有學年（一年一班／招生年）。私人若清空呢欄，專科／功輔唔受影響。刪 column 就要拆表或改成三線唔同 schema，同 C1 相反。

一併處理 `end_date`：現有 9 班全係 2026-06-30，但排程已過呢日。點名紙而家**唔睇**結束日，所以仍上到紙；畫面會誤以為班已完。建議改空，直到退讀先寫結束。
