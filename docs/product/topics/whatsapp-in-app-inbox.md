## 開工閘

**未拍板唔實作。** 2026-08-31 結論：80 戶自建不划算。本檔留作討論紀錄。現有 `/Inbox` 唔改用途。

## 結論（2026-08-31）

**約 80 個在讀家庭，自建 Cloud API inbox 不划算，先不實作。** 訊息費唔係理由（客服回覆可當 $0）；貴嘅係工程同 24 小時窗／對人／待辦兩套清單。減少切換目前繼續用現有 `wa.me`／WhatsApp 網頁（同一帳已同步）。現成平台接駁通常仲要跳第二個畫面，同樣唔抵。

值得再睇嘅情況：多人同時回、主動通知量大、或一定要喺學生頁睇對話先唔切。屆時重開波次。

系統已有：學生聯絡電話、`wa.me` 預填（[`whatsappReminder.ts`](../../../src/lib/whatsappReminder.ts)）、收件匣通知。**冇** WhatsApp 對話串。

規模（2026-08-31 production）：在讀約 77、獨立電話約 71；2627 就讀中 36。偏好已填 WhatsApp 23、WeChat 6、未填 48。

## 建議第一期（待拍板）

只做薄 inbox，唔做客服產品：

1. 現有 WhatsApp 號碼 **coexistence** 接 Cloud API（手機暫留後備）。
2. Webhook → 表；用 `wa_id` 對第一聯絡人電話。
3. **學生詳情**對話串＋回覆框；未讀可掛側欄現有收件匣捷徑（另類型，唔混入營運通知列表）。
4. 24 小時窗外：禁用自由文字，只准已批 template（或顯示「請用 WhatsApp App 回」）。
5. 唔做：廣播、分配會話、機器人、WeChat、歷史對話全量匯入。

## 自建問題

### 1. 「未讀／邊個應咗」——唔係話訊息唔同步

手機 ↔ WhatsApp 網頁版／Business Suite 而家睇到同一串回覆，因為係**同一個 WhatsApp 帳**（官方多裝置）。呢層 **唔會因為自建而斷**。Coexistence 下，API 送出嘅訊息亦會出現喺商業 App；手機送出嘅會以 `smb_message_echoes` 抄入系統。**對話內容大致兩邊都見得到。**

先前講「對唔齊」係指另外兩層，唔係內容：

| 層 | 而家（手機／網頁） | 加明學之後 |
| --- | --- | --- |
| 對話文字 | 同步，同一帳 | 內容仍可兩邊有（coexistence） |
| 未讀＝仲有無人手處理 | WhatsApp 一個未讀點；同事開咗就齊 | 明學會另有「未讀／待回」。兩套清單。API 一處理，商業 App 有時會**自動標已讀**，手機未讀點唔再代表「未回」 |
| 邊個職員回 | WhatsApp **本來就冇**：只顯示本社號碼，唔寫 Rain／Cody | 只有喺明學撳送嘅先記到登入者；手機打出去嘅 echo 只有「本社號」，系統唔知邊個 |

所以風險唔係「A 喺網頁回、B 喺手機睇唔到」。而係：有人繼續用 WhatsApp 當待辦箱、有人用明學，**待辦會對唔上**；亦唔好期望系統 inbox 做到「顯示邊個同事用手機回咗」。

營運含義：回覆入口可以繼續允許手機（內容仍同步），但**「仲未回」呢張工單只應睇明學**（或只睇 WhatsApp，唔好兩套）。呢題仍待決。

### 2. 對唔到人

- 兄弟姊妹共用家長電話 → 一條對話對多個 `students`；回覆框要揀／顯示「聯絡人：某家長，關連：A、B」。
- 區號、空格、舊 `whatsapp` 欄 vs `parent_phone`／第一聯絡人（見聯絡更新活動）。
- 未建檔試堂家長、改號、大陸號 `+86`。
- 對唔到嘅對話：需要「未配對」籃，唔好丟。

### 3. 24 小時窗（產品，唔淨係計費）

呢條牆**只綁 Cloud API**。而家用嘅商業 App／網頁版一對一，平時可以隨時打字，所以前線未見過。搬入系統用 API 回，先要跟 Meta 規則：

- 家長（或學生）**來訊** → 之後 24 小時：自由文字、圖、檔，同而家 App 差唔多；客服類唔收訊息費。
- 計時由**對方最後一句**起，職員回覆**唔會**延長窗。
- 超過 24 小時對方無再來：API **拒絕**自由文字（error 131047）。要再出聲，先送一則已批 template；對方一回，窗重新開 24 小時，又可以打字。

**其他商業機構唔係每則都用 template。** 日常客服（家長問請假、問堂、即日來回）幾乎全部喺窗內完成，打字即可。Template 只用於**我方先開口**或**靜咗超過一日要再搵人**，例如：繳費提醒、停課、補堂確認、催未回覆。客服臺慣例：窗開→輸入框；窗關→換成揀 template（常見 3–8 個：跟進／請回覆／繳費／改期），唔係每句都申請新稿。

第一期必須有窗倒數同禁用輸入，否則前線當系統壞。繳費／停課 template Meta 可能判 utility 或 marketing。逾期罰款自動通告屬另題（[`tuition-late-fee-enforcement.md`](./tuition-late-fee-enforcement.md) 不含家長自動通告）。

**仍可用商業 App 避開呢條牆**（App 一對一無 API 咁嚴），但咁又變返雙入口，同「少切」拉鋸。見待決 1。

補習節奏（多數一星期三讀、唔會天天搵人）**唔等於**要每星期都撞牆：

| 職員想做 | 窗 | 點處理 |
| --- | --- | --- |
| 只係睇舊對話、等家長嚟問 | 無關 | 歷史仍在；唔使出訊息 |
| 家長堂日問請假／補堂，即日或數小時內回 | 開住 | 打字，同而家一樣 |
| 對方上次來訊已過一日以上，我方要**先**出聲（繳費、停課、補堂確認、催未回） | 關 | 一則已批 template；對方一回又可以打 24 小時字 |
| 每週固定「聽日上課」而家長無來訊 | 關 | 當通知：每戶每週一則 template（香港 utility 約 HK$0.21），唔係每句都申請新稿 |

一星期三讀、多數被動等家長問：**幾乎唔使 template**。會用 template 嘅係主動通知（繳費、停課、每週提醒），同而家商業 App「隨時打第一句」唔同，要預先批 3–8 個稿。

追問：先送 template、家長**無回**，窗仍然關。再出聲只能再送 template，**每則送到都各計一次**（唔係 24 小時內包幾則）。對方一回，之後 24 小時先可以免費打字。

### 4. 媒體同訊息種類

語音、相、PDF、回覆引用、location：要存 Storage、預覽、大小限制。第一期可只做文字＋靜態圖，其他顯示「請喺 WhatsApp 睇」——但咁又切返去，削弱「唔切換」。  
語音轉文字、已讀、正在輸入：Cloud API 支援有限或要額外做；唔好當 WhatsApp App 1:1 複製。

### 5. 權限同隱私

家長訊息含學費、家庭事。老師應否見自己班家長對話？財務？代堂老師？  
現有收件匣老師可見營運事件；**家長對話唔應默認跟同一套可見範圍**。RLS 要另設計（anon key 在瀏覽器）。

### 6. 同現有「收件匣」撞名

側欄「收件匣」＝內部通知。加家長對話若都叫收件匣，老師會以為營運通知同家長訊息係同一堆。  
要另名（例如學生頁「對話」）或收件匣加**第三分頁**並寫清對象。

### 7. 歷史同過渡

Business Suite／手機舊對話 **唔會**完整自動變成系統記錄。上線日起新訊息先有。職員問「舊 chat 去咗邊」要預先講。  
Coexistence 要商業 App 間中打開（文件常見約 14 日），否則 API 伴生會斷。

### 8. Meta 帳戶同營運負擔

綁信用卡、顯示名稱審核、template 審批、品質評級（濫發 template 可限流）。  
Webhook 重試、亂序、重複 `wamid` 要冪等。長效 token／system user 輪換。呢啲無現成客服臺就全部自己睇。

### 9. 覆蓋唔晒聯絡渠道

在讀裡已填 WeChat 至少 6 戶、大半未填偏好。自建 WhatsApp **唔取代 WeChat**。目標只係「WhatsApp 家庭少切」，唔係統一通訊中心。

### 10. 工程量 vs 人數

80 個家庭、客服費近 $0。自建第一期（webhook＋對人＋學生頁文字回覆＋窗）仍係一條產品線：schema、Edge Function、RLS、未讀、失敗重試、流動裝置。  
現成平台月費大約 HK$230–1,200，但職員主畫面會喺平台唔喺明學——**接得到資料 ≠ 唔切換**。
