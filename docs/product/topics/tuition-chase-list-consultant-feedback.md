## 1. 一句總結

**方案骨幹正確，不需要重寫。** 以「常規第 N 期」為單位、行＝學生 × 組別、點列即開右側解釋——呢個方向喺同業度搵唔到更貼身嘅做法（見 §3），值得保留。

要執嘅唔係方向，係：

1. **三個邏輯位**（§5 P1/P2）：假期窗跳期、冇池組別變假欠、隊列唔認負餘額；
2. **一條真源接縫**（§4 Q4、§5 P2-2）：期數追收與曆月建議並存時嘅 double-count 與「0＝唔使交」矛盾；
3. **一套發佈配套**（§6）：用語表、前線指引、收據帶期名——「期」對家長先唔係黑盒。

另：意見會受我未睇 production 數據限制（§8），步 4 抽樣對庫必須喺 UI 驗收前完成，唔可以拖到發佈後。

## 2. 我點理解明學嘅收費模型（本文判斷基礎）

- **三線商業模型**：專科班＝賣「學年內嘅堂」（報讀入學年，預繳堂數，點名屬計費先扣）；私人課程＝賣「關係內嘅堂」（無學年容器、可跨年）；功輔＝賣「某曆月到校權」（月費，無堂數結餘）。
- **已繳堂數按組別共用**（權益池 v3 拍板）：**同一級嘅專科班＝一個錢罌**——實作上 `resolveEntitlementNamespace` 對專科班只睇年級唔睇科（即全級專科一個池，條件係同價同規則）；私人另池；試堂分離。**呢點比 backlog 文字形容嘅「同級專科共用」仲激進**，解釋責任落晒前台（見 Q7）。
- **校曆（附件甲）**：十期，每星期幾各四堂，期與期曆日交錯；收費實務「約每月四堂、每科」。
- **罰款引擎**：$50／科／曆月（10 月 1 日生效），頻率按曆月、判定按已扣＞已繳——**同追收頁嘅「期」係兩套週期**（見 Q1、§6）。
- **現有工具**：終身追收 RPC、堂數對帳頁、AI 追收摘要＝「全學年／終身」口徑；本頁填嘅係「**未來排程有冇錢覆蓋**」嘅預視。兩者分工正確。

## 4. 對 backlog 九問的意見

### Q1. 追收單位用「常規第 N 期」正確嗎？

**正確，支持。** 附件甲的曆日交錯令曆月窗算唔啱（一個月 4–5 堂浮動、聖誕／農曆年斬開），用日期集合分桶係唯一正確做法。呢個改動唔係矯枉過正，係必要修正。

兩個風險要補：

1. **兩套週期並存**：追收行「期」、罰款引擎行「曆月」（頻率）。期界與月界錯開時（例：第二期星期二 29/9 已開始），會出現「追收頁話唔使收、罰款引擎照加 $50」嘅表面矛盾。唔係數字矛盾（兩者同用一個尚餘做基礎），但**前台需要一句話術**：「追收頁講收幾多堂；罰款係另一套按曆月計嘅規則。」
2. **「期」對家長係黑盒**：家長腦入面係「月」。現行收據冇期名、冇曆日。**收款時單行 description 應自動帶「常規第 N 期」＋首尾上課日**（右側排程明細已有一切資料，只差組裝）。做唔到呢樣，「期」永遠要前台口頭解釋。

### Q2. 「一次過可收＝本期＋下期」會否過度預收？

**憂慮一半成立。**「一次收兩三期」係明學既有習慣（8 月交 9 月、9 月交 9–11 月），所以選項本身貼地、可保留。要執嘅係**包裝同語義**：

- 而家右側三格並排、`一次過可收` hint 寫「出單時可一次收齊」——視覺上變成默認建議，唔好。
- 建議：`一次過可收` 降格為「若家長願意，可一次收齊 N 堂（兩期）」嘅次級說明句／tooltip，主強調放返「本期要交」。例：「非硬性；收足本期即可。」
- 觀感考慮：以《教育規例》精神同翹英案後嘅敏感度，預收上限「一個月多啲」係安全區；你哋現行政策已超出，**呢個係收費政策問題，唔係今期工程可以／應該改**，但新 UI 唔好再落井下石。

### Q3. 隊列少計，可接受嗎？

**可接受，但少計嘅真風險唔係你講嗰個。**

你指出嘅「現在要追嘅人同時欠下期，唔會重複喺下期隊列」——正確，可接受，補註已做足，而且係刻意設計（前台優先處理「而家」）。

真正要驚嘅係**相反方向嘅少計**：一個**尚餘為負（已上未付）但本期已冇未點名排程**嘅學生（點名積壓、期末、或該組本星期幾已過），`本期要交＝0、下期要交＝0` → 被標成「**已預繳**」收埋咗！呢個先係「少計」。修正極簡單：**尚餘＜0 一律入「現在要追」**——隊列優先序：欠款（負餘額）＞本期要交＞下期要交。

### Q4. 收款登記自動建議（曆月）與本頁（期數）並存

**建議：唔好急住全面「統一成期數」；要分清楚「行級」同「池級」各自啱用咩口徑。**

另一份評審（consultation.md Q4）主張「必須統一成期數」。我部分不同意——純因為：

- **曆月喺系統內有佢真正嘅主人**：功輔覆蓋月、罰款頻率、部分營運報表。全面改期數會製造新對帳問題。
- **行級自動建議嘅真正毛病唔係「月 vs 期」，而係「減池餘」本身喺 shared namespace 下計唔啱**（見 §5 P2-2）：同一組別兩班時，每行各自「全組別會扣 − 池餘」→ **double-count**。呢個問題改成期數都一樣存在。

**建議方向**：

- 行級建議＝「**該行班別喺期內嘅未扣排程數**」（即每科 4 堂左右嘅節奏），唔減池餘；
- **池餘缺口由池級嘅 chase box 話你知**（而家 /Payments 摘要加咗，啱）；
- 拆數（呢 8 堂點分落中英數）由前台用右側排程明細決定，或按各科期內未扣排程自動拆好（見 Q7）。
- 錢罌係池級、單據行係科級，中間嘅拆數**唔應該由自動建議扮識計**。

### Q5. 右側欄密度

**必須一眼睇到（4 個）**：本期要交、下期要交、尚餘可扣（負數紅）、一句「點解唔使收」。
**可以收細／摺疊（4 個）**：一次過可收（降為說明句，Q2）、本期已扣（淨數字）、本期還會扣＋下期會扣（兩格可合成一行「本期／下期還會扣」，明細入清單）、已收款堂數。

三個具體位：

1. **尚餘可扣而家出現兩次**：header 嘅 DuePair 一次、統計格一次（實作確認，`TuitionChaseDuePair` 收 `remainingLessons` 而 grid 又有「尚餘可扣」stat）——header 有咗就抽起 grid 嗰個，騰位。
2. **排程明細清單（日期時間逐條）好長**：一次收 24 堂嗰陣 rail 會冇晒位。清單係解釋用，設「顯示明細」開關／收喺 Section 內點先展開，但**計數格唔好收埋**。
3. **whyText（一句說明）係全個設計最值錢嘅嘢，唔好收埋**——要喺數字下即見，唔好墊底。

### Q6. 用詞張力（發起人特別叫顧問睇）

發起人較早批評「N 月要交」個數字實係消耗、唔係要交——**批評正確**，改「共扣堂數」係必要修正；後嚟又要求「本期／下期要唔要收、收幾多」一眼睇到——**兩套數字都真係需要**。解決方法唔係揀一邊，係分層鎖死語義，守一條規則：

> **動詞（行動）組：「本期要交／下期要交／一次過可收」——永遠「收錢」語義，0＝「不用收」。**
> **名詞（庫存）組：「尚餘可扣堂數／本期已扣／本期還會扣／下期會扣／已收款堂數」——永遠「堂數流水」語義。**

畫面已經係咁分兩層（header「要交」對統計格「已繳與扣堂」），方向啱。細位要執：

- 統計格而家用「尚餘可扣」，用語表要求「尚餘可扣堂數」——**同用語表對齊**（TERMINOLOGY／.cursor 同步見 §6）。
- 「尚餘可扣堂數」對前台仍係三個詞砌埋，tooltip 寫法用返發起人自己嗰句：「**已繳而未扣**（呢個組別袋裏面仲有幾多堂）」。唔好用「權益」字眼。
- 「已預繳」呢個隊列名：對「剛好夠、冇欠」嘅學生都叫「已預繳」稍有名不副實；「唔使收」／「已繳足」可能更準。命名品味，非 bug——但負餘額學生**唔可以**出現喺呢組（Q3），否則「已預繳」三個字同紅色負數並排就係「系統出錯」嘅最佳劇本。

### Q7. 同一級專科班共用、家長按科交——點解「呢一組要收 N 堂」

實作粒度比 backlog 形容更大：專科班**只睇年級、唔睇科**（成級一罌，前提同價同規則）。解釋責任因此更重。前台可用講法（建議入指引）：

> 「你嘅已繳堂數係按級共用嘅：中一嘅中文班同數學班用同一個結餘，上堂先逐堂扣。今次呢一組要收 N 堂，係兩班下期堂數加埋。」

證據鏈其實已有齊：每條已收款列科名（單據行）、每條排程列科名——「數字係級級計，但每筆錢、每堂課都對得住科」。缺嘅係三樣包裝：

1. **組別 label 列出涵蓋範圍**：「專科班（中一）· 中文、數學」——一眼知呢罌錢包住邊啲科。
2. **要交 N 堂嘅拆數建議**：按各科期內未扣排程，自動拆「中文 4、數學 4」嘅預設，唔使前台心算。
3. **收據分科照舊**（D11 已拍板，同意，唔好改）——唔好為共用而改收據格式。

**必須核對嘅前提**：若同級唔同學科單價唔同，成級一池已違反 v3「同價同規則」——呢個要喺步 4 抽樣時一併核實，否則池嘅組成錯咗都冇人知。

### Q8. 尚餘為負會唔會俾人當系統出錯

**會，但現有補救（淡紅＋計入要交＋tooltip）方向啱，力度唔夠。** 三個位要加固：

1. **負數一定要伴隨人話長註**，唔好齋 hover：「即已上課未付款 N 堂」。另一份評審建議引入「過往欠堂／已透支」獨立概念——我同意佢嘅動機，但認為唔使開新術語系統：負數＋一句人話＋計入要交已經夠，**開咗「欠堂」就要同「要交」喺隊列度定義清楚點疊**（見 Q3，嗰個先係真 bug）。
2. **隊列唔可以叫負數學生「已預繳」**（Q3）。
3. **點名滯後會令負數時隱時現**（未點名＝「還會扣」，尚餘未反映；點完即負）。指引要寫：「尚餘以畫面為準；發現老師成日遲點名係跟進老師嘅事，唔好同家長拗。」

### Q9. 範圍（功輔唔入、僅暑期／僅私人唔入）

**正確。**功輔月費另一套口徑；僅私人無 2627 節奏——唔入預設名單啱。但三個補漏（兩個係實作問題，唔係範圍決定錯）：

1. **暑期開頁冇空狀態**：2627 期數表得十期，暑假（7–8 月）開頁會話「而家係常規第一期」（9 月嗰期）——顯示九月追收數係錯嘅。暑期應該顯示「常規學年未開始／暑期不適用」。
2. **僅私人組別而家會以「尚餘 0」入隊列**：私人池喺 production 根本未建（見 §5 P1-2），全部變假欠——呢個唔係「唔入名單」解決到，係數據層 bug。
3. 空狀態文案要解釋「功輔唔適用於本頁」，唔好淨係「冇可追收」——免得前台以為漏咗功輔學生。
