## 專家覆核（2026-10-16）

原調查的資訊架構方向採納（主按鈕看整列、拆開「其他結果」裡的開放狀態、預設待跟進、已過堂圓鈕）。以近二十天真實轉化個案衡量，不可只整理列表：功課輔導班轉正原先鎖死試堂班，已就讀班被班別選單排除，黃偉捷／黃韻澄／鄭煒霆會結不了案。

| 原方案 | 覆核 |
| --- | --- |
| 已可上紙且已點名或試堂日已過：正式報讀與標流失並列 | 正式報讀做實心主按鈕，標流失做可見次動作 |
| 「改班能力保留」 | 只對專科班屬實。功輔／私人原先鎖死試堂班；本輪功輔可改選其他功輔班 |
| 三種結束＋轉化率大卡 | 前線不放轉化率；已結束檢視才顯示已正式報讀／已流失／其他結果 |
| 家長考慮中改列上備註即可 | 本輪夠用。不做下次聯絡日、負責人、銷售工作台 |
| 建議先後：按鈕 → 第一屏 → 新增 | 改為：佇列與結果 → 功輔改班與連結既有報讀 → 數字／欄位／新增對話 |

已知殘留（本輪不改）：學生頁報讀沒有試堂未點名警告；`closeOpenTrialsAfterEnrollment` 只關同一班。點名紙已完成仍可上紙（秦錦怡那類）已修，不要倒退。

明確不做：手機卡片、銷售工作台、自動化催跟進電郵、下次聯絡日欄位。

## 維持不變

- 試堂頁只登記試堂。半價、原價、免費（含 $0）都到收款登記出單，確認收款後才上點名紙。
- 取消、刪除、改期若已有出席，必須一併刪除，沒有保留出席的選項。
- 正式報讀仍在本頁對話完成；專科可改班、選開始日；功輔選日數檔。功輔可改選其他功輔班。已就讀則連結現有報讀，不新增一筆。私人課程仍報讀試堂那一班。
- 手機卡片列表仍屬 [`mobile-ui.md`](./mobile-ui.md) 的 T5，本方案不先做。

## 這一頁在答什麼

一筆試堂在畫面上有四個彼此獨立的事實。

| 事實 | 畫面 | 誰改 |
| --- | --- | --- |
| 堂本身 | 狀態：已預約／已完成／取消 | 標籤；取消在「更多」。正式報讀或結束結果時，系統把未取消的列改成已完成 |
| 跟進結論 | 結果：待跟進／已正式報讀／已流失／其他結果 | 正式報讀、標流失、其他結果 |
| 錢 | 未出單／待收款／已收款可上紙 | 收款登記 |
| 有沒有點過名 | 已點名／未點名 | 點名紙；本頁只顯示 |

主按鈕看整列（結果、取消、收據閘門、點名、試堂日），不只看錢。程式：`src/lib/trialFollowupAction.ts`；閘門在 `src/lib/trialReceiptGate.ts`；結果是否結束在 `src/lib/trialOutcome.ts` 的 `trialOutcomeClosed`。

## 問題

### 1. 「其他結果」會把人移出待跟進，選項卻寫成還在跟

登記其他結果後，`outcome` 改為已結束，未取消的狀態改成「已完成」（`recordTrialOutcome`）。該列主按鈕消失，不能再改期，也不能正式報讀。

對話框說明寫「例如改期、暫掛跟進」。選項有「改期再試」「家長考慮中（暫掛）」「只試不報（明確）」。

真正的「改期」在「更多」裡，只換 `schedule_id` 與試堂日，結果仍是待跟進（`rescheduleTrialSession`）。職員若選「改期再試」，效果相反：人從待跟進消失，堂次也不會改。

「只試不報（明確）」放在其他結果，不計入流失。轉化率分母卻是「轉化＋流失＋其他」。上方卡片只有已轉化、流失、待跟進，沒有「其他」。註腳寫「轉化 ÷（轉化＋流失＋其他）」，畫面上看不到「其他」的數字，三個數對不出那個百分比。

### 2. 已取消的列，主按鈕仍可能是去收款

`needsReceipt` 只看收據閘門，不看狀態。

- 待跟進、已取消、未可上紙：主按鈕仍是「前往收款」。
- 待跟進、已取消、已可上紙：主按鈕是不能按的「正式報讀」（`trialCanConvert` 拒絕已取消），旁邊小字「已取消，不可轉正」。該做的「標流失」在「更多」。
- 待跟進、已可上紙、未點名、試堂日未到：主按鈕已是「正式報讀」。未點名會先警告，但這一列沒有「等上課」。

### 3. 狀態下拉和點名標籤各說各話

每一列都能把「已預約」改成「已完成」，沒有確認，也不要求已點名。取消和這兩個狀態放在同一個下拉；取消會刪出席。

「已完成」另外會在正式報讀（`convertTrialToEnrollment`）或其他結果時由系統寫入。同一列可以同時是已預約、已點名、待跟進、已收款可上紙。四個標籤都對，下一步要職員自己拼。

### 4. 上方數字不是這張表

| 區塊 | 實際在數什麼 |
| --- | --- |
| 轉化率、已轉化、流失、待跟進 | 目前載入的全部列（`rows`），不跟搜尋或篩選走 |
| 今天試堂、本星期試堂 | `fetchTrialDashboardStats`：資料庫該日全部 `trial_sessions`，含已取消，也不跟本頁的學年隱藏走 |
| 已關聯收據 N／M | 凡有 `payment_id` 都算，待收款也算 |

點「今天試堂」只是把表的日期篩成今天，卡片數字不會變成表底的筆數。快捷圓鈕「未可上紙」是未出單加待收款，和「已關聯收據」不是同一件事。

### 5. 同一組篩選出現三次

「待跟進」是卡片，也是圓鈕，也在「更多篩選」的結果列。「今日」是「今天試堂」卡片，也是「今日」圓鈕。點圓鈕會讓「更多篩選」出現數字，因為它們改的是同一組狀態（`activeFilterCount` 含 `outcomeTab`、日期、`receiptTab`）。

「未可上紙」只存在於圓鈕。篩選面板是未出單、待收款、已收款可上紙三個，沒有這個合計。

### 6. 新增試堂有幾處對不上列表

- 類型有「體驗課」。去收款時，不是半價或原價都當成免費（`trialPay=free`）。篩「免費試堂」用 `trialTypeCategory`，字串含「體驗」也算免費。列上仍顯示「體驗課」。
- 「計老師人頭」必填、沒有預設。列表不讀這個欄，`updateTrialSession` 也不能改它。
- 網址有 `studentId` 就 `setAddOpen(true)`，不會把列表收成該生。帶了班別或堂次才是要預填新增。
- 學生選單要先打字才出現；班別一聚焦就列前 20 個，沒有年級限制。正式報讀對話已用可搜尋選單，新增對話是另一套。

列表九欄，表寬至少 1080px。沒有列時只有「此條件下沒有紀錄」。

### 7. 功輔轉正鎖死試堂班；已就讀班選不到

正式報讀對話功輔／私人把報讀班鎖為試堂班；班別選單濾掉功輔，並排除已就讀班。中學部功輔試堂改報小學部、或人已報讀只差結試堂，都無法在本頁完成。

## 改法

預設只回答：還有哪些待跟進，下一手是什麼。復盤改成看已結束的紀錄時才出現，而且數字跟當時已載入的列走。

### 列的主按鈕

| 條件 | 主動作 |
| --- | --- |
| 待跟進、未取消、未可上紙 | 前往收款 |
| 待跟進、已可上紙、未點名、試堂日未到 | 不放主按鈕，標示上課日。正式報讀留在「更多」 |
| 待跟進、已可上紙，而且已點名或試堂日已過 | 正式報讀（實心主按鈕）；標流失為可見次動作 |
| 待跟進、已取消 | 只留標流失 |
| 已正式報讀、已流失、其他結果 | 顯示結果與原因，不再給主按鈕 |

改期、刪除、取消、寫備註留在「更多」。取消沿用現有出席確認。狀態改為標籤，不再在列上直接改成已完成。已完成只在正式報讀或登記結束結果時由系統寫入。已點名仍留在時間旁。

### 結果

只保留三種結束：正式報讀、不會報讀（流失）、其他結果（稀有，必填備註）。

- 「只試不報」改為流失原因。
- 拿掉「改期再試」。改期仍只用「更多」裡的改期。
- 「家長考慮中」改為待跟進列上的備註，結果維持待跟進。
- 其他結果的說明寫明：登記後離開待跟進，不能再改期或正式報讀。改報其他班請用正式報讀。
- 卡片、按鈕、對話框、成功提示統一寫「正式報讀」「已正式報讀」「已流失」。

### 正式報讀對話

- 專科：可搜尋改選尚未報讀的專科班；已就讀的專科班標「連結現有報讀」，確認後只結試堂、不新增報讀。
- 功輔：可搜尋改選其他功輔班（含小學部／中學部）；已就讀則同樣連結，不新增。
- 私人課程：仍報讀試堂那一班。

### 第一屏

- 預設待跟進（檢視：待跟進／已結束／全部）。
- 圓鈕：未可上紙、今天、試堂日已過仍待跟進。
- 搜尋仍是姓名或電話。
- 「更多篩選」留狀態、類型、老師、年級、科目、註冊、日期、收款三態。結果篩選不要再複製一套。
- 今天、本星期用這一頁已載入的列來數，並註明含已取消。不要用另一條全庫計數。
- 收據那一行改為「已可上紙 N／M」，與未可上紙同一套閘門。
- 轉化率只在已結束檢視：已正式報讀、已流失、其他結果都出現。

### 列表

五欄：日期與時間、學生、班別、類型、下一步。收款與點名放進下一步。計老師人頭在下一步旁用小標顯示。

空列表在有篩選時提供清除篩選；完全沒有紀錄時提供新增試堂。

### 新增對話

- 學生和班別都用可搜尋選單。
- 類型只留免費、半價、原價。既有「體驗課」列顯示為免費試堂。
- 網址只有 `studentId` 時篩該生，不打開新增。帶了班別或堂次才打開新增並預填。
- 建立後仍前往收款登記。
