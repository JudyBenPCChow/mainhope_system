## 一句

`ScheduleManagePage.tsx` 同時負責日期來源裁決、URL 雙向同步、快取、查詢、日視圖與多種寫入操作。現時功能可運作，但改動容易跨越多組 effect 與狀態邊界；本題以行為測試先鎖定現況，再逐步抽出 controller、資料 hook 與畫面區塊。

## 開工閘

- **現在只立項，不實作。**
- 清單資料快取見 [`list-data-cache.md`](./list-data-cache.md)；分支 `cursor/22710242`（遠端 `d0644f95`）尚未合入 `main`。開始本題前須先確認該分支已合入或已關閉，並以最新 `origin/main` 重新盤點。
- 先寫日期來源與請求競態測試，再搬動程式；不可用重寫整頁取代漸進拆分。
- 本題不得順帶改排程、點名、補堂、代堂或課室佔用的產品規則。

## 現況與風險

截至 `cursor/22710242` 的 `8dea8841`：

- `ScheduleManagePage.tsx` 約 3,239 行，集中大量 state、effect、查詢與操作對話框。
- 初始日期來自四層：URL 深連結、同範圍記憶體快取、未來最近排程、今天。
- 日視圖會把日期寫回 URL；初始化時須避免先把「今天」寫回並覆蓋最近排程。
- 主列表已有 request generation guard；部分列展開資料仍可能被較舊請求覆寫。
- `todayYmd` 在元件 render 時計算，頁面跨午夜長時間開啟時可能仍指向前一天。

行數本身不是缺陷；風險在於多個可獨立失敗、獨立測試的責任仍由同一元件協調。

## 目標邊界

1. **日期與範圍 controller**
   - 明確實作並測試優先次序：有效 URL → 同角色範圍且相符的快取 → 未來最近排程 → 今天。
   - 管理 `displayStart`、`dayViewDate`、`startInitialized` 及 URL 雙向同步。
2. **清單資料 hook**
   - 管理排程列、課室、名單 context、alerts、統計、載入世代及快取失效。
   - 所有可能逆序完成的請求均須拒絕過期結果。
3. **畫面與操作區塊**
   - 日視圖、列表、展開名單及各操作對話框按既有領域邊界拆出。
   - 寫入仍走既有 services；父層只保留頁面編排與跨區塊狀態。

## 驗收

- URL 深連結日期永遠優先，不會先顯示或查詢另一個快取範圍。
- 無 URL 時，新鮮且鍵相符的快取可即時還原；過期資料只作 stale 顯示並靜默重抓。
- 無可用快取時使用未來最近排程；查詢失敗或沒有排程才回到今天。
- 日視圖寫回 URL 不會覆蓋初始日期裁決，也不造成重複導航或重複載入。
- 切換日期、角色範圍或展開項目時，較舊請求不可覆蓋較新結果。
- 桌面／流動裝置及行政／老師既有可見性、操作與返回行為不變。
- `npm run test`、`npm run lint`、`npm run ui:check`、`npm run build` 通過。

## 建議波次

1. 補日期優先次序、URL 同步及 request generation 的純函式／hook 測試。
2. 抽出日期與範圍 controller，不改 JSX。
3. 抽出清單資料 hook，統一快取鍵、載入及過期請求處理。
4. 按既有邊界搬出日視圖、列表及操作區塊；每一波均做角色與裝置回歸。

## 明確不做

- 不把本題併回已關帳的「前端架構邊界／God files」。
- 不因拆檔而新增另一套排程資料模型或狀態管理框架。
- 不改 `schedules.teacher_id`／`classes.teacher_id` 的代堂規則。
- 不刪除或改寫 `makeup_of=<取消堂id>`。
