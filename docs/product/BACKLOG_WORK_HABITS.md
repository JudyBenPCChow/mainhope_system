# Backlog 決策與工作習慣（給另一個 agent）

本檔描述**產品／決策者**如何用 backlog 做決定——唔係制度骨架本身（骨架見 [`BACKLOG_SYSTEM.md`](./BACKLOG_SYSTEM.md)）。  
另一個 agent 應把下面當協作契約：跟呢啲習慣做事，少問錯問題、少擅自實作。

來源：MainHope 專案對話、分題（尤其報讀權益、學年鎖、連堂、計糧、2627 守則）、以及明確指示「擺入 backlog／先不實作／模擬」。

---

## 1. 一句總覽

Backlog 係**外置決策記憶**：先寫清問題與選項 → 產品拍板寫入分題 → 工程只跟已拍板句；未拍板就唔開工。  
「有冇記低」同「可唔可以做 code」係兩件分開嘅事。

---

## 2. 進場分級（idea → 跟進 → 開工）

| 階段 | 放邊 | 意思 | Agent 該做 |
| --- | --- | --- | --- |
| 單純構想、未決定做 | `docs/FUTURE_*.md`（或同等構想檔） | 靈感庫；**唔係**承諾 | 寫／更新 FUTURE；**唔**加 BACKLOG 列、**唔**實作 |
| 已討論、認定要跟進 | `BACKLOG.md` + `backlog/<topic>.md` | 正式追蹤；可仍係 `open`／idea | 加索引列＋分題；寫範圍／不含／待決；**預設仍唔實作** |
| 開工中 | 同上，狀態 `in_progress` + 可選 `plans/` | 可寫 code | 只跟已拍板範圍；進度回寫摘要一句 |

用戶原話級約定（曾明確確認）：

> 單純 idea／未決定做 → FUTURE  
> 已經討論過、認定要跟進 → backlog  

常見口令：「擺入 backlog，先不實作」＝記需求、寫待決；**零產品 code**。

---

## 3. 決策喺分題點樣發生

### 3.1 先結構化，再請拍板

Agent／分析先把問題寫進分題，唔好只喺 chat 問完就散：

- **待決**：選項表，常留空白「決定」欄等產品填  
- **問題／為什麼重要／選項**（複雜題，如學費池 D1–D9）  
- **不含／本期不做／暫緩**：同「要做」一樣正式  

產品回覆後，agent **必須回寫分題**（唔好只留喺對話）。拍板後升級為例如：

- `## 已拍板產品句（工程必須跟）`  
- 或待決表「決定」欄填實、刪掉未選項  

工程實作時：**只准跟已拍板句**；未決項繼續留喺「仍要你決定」。

### 3.2 拍板可以改路線，甚至整題取消

習慣係**可逆、有紀錄**，唔係死守初案：

| 例子 | 做法 |
| --- | --- |
| 學年鎖整固 → 撤硬鎖＋confirm | 舊主題 `cancelled`；新主題另開；舊分題留原因 |
| 原班連堂分節點名 | 行政模擬發現缺口 → 產品以「實務幾乎唔會」`cancelled`；寫清取消原因，避免日後撈亂 |
| 生命週期 O0／O5 | 標 **本期不做**；需要時另開主題，唔硬塞同一期 |

取消／暫緩都要寫進分題：**點解唔做**、同邊啲相關項**唔好混**。

### 3.3 範圍用語（產品常用）

| 用語 | 意思 |
| --- | --- |
| 本期 | 而家呢波要交付嘅邊界 |
| 下一波／另題 | 承認有價值，但唔喺本期；可留 open 或只寫喺分題「工程下一波」 |
| 暫緩・勿刪 | 死碼／殘頁可能重用；清碼 agent **禁刪**直至產品明確退役 |
| 先不實作 | 只入 backlog／文件 |
| 不要實作 | 本輪只分析／模擬／寫方案；違反會被嚴厲糾正 |

## 4. 開工前閘門（強烈偏好）

複雜或高風險主題，產品常要求 **先文件／模擬，後 code**：

1. 方案寫入 backlog 分題  
2. **不要實作**——改做：前線操作模擬、學費／權益影響模擬、對抗／角色模擬  
3. 結果回寫分題  
4. 產品用模擬結果調「已拍板句」或取消項  
5. 先有明確拍板／計劃 Wave，先至實作  

曾發生：用戶已講「不要實作」，agent 仍寫 code → 視為嚴重違約（未找齊問題就改，易加 bug）。  
**預設**：指令含「模擬／方案／盤點／列入 backlog」而無「實作／開工／落地」→ 只動 docs。

## 5. 點樣用 backlog「做決定」（產品視角）

### 5.1 外置大腦，唔靠對話記憶

- 日記／會議／阻塞 → 抽出跟進寫入／更新 backlog  
- 「等 Mark 回覆」類外部依賴 → 更新索引一句摘要＋分題主阻塞  
- 問「有咩未做」→ 只信 `BACKLOG.md` 進行中表，唔靠 agent 即興回憶

### 5.2 一次拍一批，寫成可執行句

偏好：agent 整理成可勾選／可填表嘅待決 → 產品一次回覆多項 → 固化成**工程必須跟**嘅產品句（例：池真源、罰款不入池、建議公式）。  
未答完可以留「仍要你決定」；**唔好**用猜測當拍板去寫 code。

### 5.3 用「不含」同「取消」控風險

決定唔只係「做咩」，更常係「邊度停」：

- 計糧：正式引擎 `done`，功課班／費率頁明確下一波  
- 成本統計：純利另題；按金等**產品決定**先寫喺下一步  
- 死碼清理：可清 vs 暫緩勿刪 分開寫死  

### 5.4 對抗／顧問意見要回寫，但拍板權喺產品

顧問／對抗報告可掛喺分題旁（如 consulting-review、audits）；產品採納邊啲，寫入「已拍板」或改待決。  
Agent 唔好把顧問建議自動升級成已定案。

### 5.5 大題分期，開口最低包可另講

大主題（例：報讀權益）用 Wave；計劃寫死遷移／回填。  
產品有時會用人話釐清「開口前最低包」（先 A＋B，C／D 可後）——agent 應寫回 plan／backlog，**未改文件前唔好擅自改節奏**。

## 6. Agent 協作 checklist（跟此人合作時）

**要做**

- [ ] 構想 vs 跟進：分清 FUTURE 與 backlog  
- [ ] 「擺入 backlog／先不實作」→ 只改 docs；回報索引列＋分題路徑  
- [ ] 待決寫成選項表或「問題／為何重要／選項」；回覆後回寫「已拍板／決定」  
- [ ] 索引摘要保持一句；細節進分題  
- [ ] 完成／取消：改狀態並**搬表**；分題留原因  
- [ ] 模擬／影響／對抗結果回寫分題，再等下一步指示  

**唔好做**

- [ ] 未拍板就實作「順便做埋」  
- [ ] 只喺 chat 達成共識、唔回寫 backlog（下一輪會失憶）  
- [ ] 把 `done`／取消項當待辦再推銷重做  
- [ ] 刪「暫緩・勿刪」殘碼  
- [ ] 為求全面而掃晒已完成表／舊 adversarial 當現行任務  
- [ ] 用顧問／模擬建議冒充產品已定案  

**指令模糊時**

- 有「模擬／方案／盤點／列入」→ 文件優先  
- 有「開工／落地／實作／apply migration」→ 先對齊已拍板範圍同現行 plan  
- 不確定屬 FUTURE 定 backlog → **問一句**，或先按「未決定做＝FUTURE」從嚴

## 7. 可直接貼畀另一 agent 嘅短版

```text
用戶用 backlog 做外置決策記憶，唔係叫你一有 idea 就寫 code。

分級：
- 未決定做 → FUTURE_*.md
- 認定跟進 → BACKLOG + backlog/<topic>.md（可仍 open／先不實作）
- 開工 → in_progress + 現行 plans/；只跟分題「已拍板產品句」

習慣：
- 先寫待決／選項／不含，產品拍板後必須回寫分題
- 「不要實作／先模擬」= 只 docs／audits；違規會被糾正
- 可取消整題或標本期不做；取消原因要留喺分題
- 暫緩勿刪 ≠ 待清碼
- 問未做只讀 BACKLOG 進行中表；細節開分題；唔預讀全部 audits

你嘅預設動作：結構化寫入 → 等拍板／等「開工」口令 → 再改產品 code；進度回寫索引一句＋分題。
```
