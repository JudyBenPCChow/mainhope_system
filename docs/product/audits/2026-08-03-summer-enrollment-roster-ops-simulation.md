# 報讀包裝 vs 點名權益：前線操作模擬

| 欄位 | 值 |
| --- | --- |
| 日期 | 2026-08-03 |
| 環境 | 桌面推演（未實作、未啟動 UI） |
| 方案依據 | [`docs/product/topics/summer-enrollment-roster-consistency.md`](../backlog/summer-enrollment-roster-consistency.md)（暫定傾向 B 權益池＋到課宣告） |
| 角色 | 前台／行政日常處理（點名紙、安排補堂、請假、救場加名） |
| 目的 | 評估若真落地，前線會否遇到操作／日常處理困難 |
| 結論 | 主路徑（取消→安排補堂→點名）會明顯順；日常難度轉移到「請假三選一」與「有餘額 ≠ 今日出名」的心智與 UX。若宣告唔夠自動、多入口規則唔齊，日常會短暫惡化。 |

---

## 1. 研究角度

### 1.1 問題設定

不評估會計認列、也不重做第一性原則盤點（該檔已有）。只問：

> 若主帳採 **B（有命名空間嘅權益池）**，點名紙只靠 **到課宣告**（禁日期推期數），前台人員日常會唔會更難做？

### 1.2 方法

1. **對照現行心態**：前線直覺係「收咗幾堂錢，就應該嚟幾堂；改期唔改有冇份」；痛點係點名紙跟唔上；逃生係人手加名。
2. **對照現行入口**：班別詳情「安排補堂」vs「新增排程」、請假管理／點名、手動加名救場（見 [`LEAVE_MAKEUP_CONSECUTIVE.md`](../manual/LEAVE_MAKEUP_CONSECUTIVE.md)）。
3. **場景推演**：以觸發個案（一期生跨期補回缺人）為錨，再擴到請假、提早交費、轉科、學年邊界、多入口名單。
4. **判準**：操作步驟是否增加、決策是否要新概念、忙時能否完成、錯選後可唔可以發現。

### 1.3 非範圍

- 未實作、未量測真實點擊或查詢時間。
- 不裁定會計／消課收入口徑（backlog 已標另開）。
- 不比較方案 A 全面落地的前線成本（只在結論中點出與 B 的差異）。

## 2. 模擬前提（摘自 backlog 暫定）

| 層 | 假設 |
| --- | --- |
| 權益帳 | 命名空間池（班／期包裝／科）；收 N＝可嚟 N |
| 到課宣告 | 決定點名紙；有餘額本身唔自動掛晒所有堂 |
| 變換 | 取消／請假／延期／補堂＝改 delivery 與權益連結；請假／調堂／順延分開 |
| 手動加名 | 若保留 → 補宣告＋原因＋audit，唔係只塗紙 |
| 學年界 | 暑期權益唔入場 9 月新正規；正規補堂落暑假日曆仍耗正規權益 |

## 3. 場景發現

### S01：一期生、取消後補回落二期日曆（觸發個案）

| 項目 | 內容 |
| --- | --- |
| 步驟 | 已取消堂 →「安排補堂」→ 開補回日點名紙 |
| 預期 | 原堂已宣告學生自動帶到新堂；黃渲棋類缺人消失 |
| 前線體感 | **變易**——對齊「改期唔改有冇份」 |
| 殘餘風險 | 若仍用「新增排程」補洞，宣告可能唔跟 → 又缺人或亂加 |

### S02：開堂前核對點名紙

| 項目 | 內容 |
| --- | --- |
| 步驟 | 開 `/Attendance` 或排程點名紙，對家長「今日應嚟」 |
| 預期 | 已宣告者穩定出現；未宣告即使有餘額亦唔出現 |
| 前線體感 | **半易半難**——正常班更穩；新投訴係「交咗錢點解冇名」 |
| 含義 | 畫面若唔顯示「餘額／今日點解有冇」，會逼返人手加名 |

### S03：請假一堂（扣堂／保留調堂／順延下期）

| 項目 | 內容 |
| --- | --- |
| 步驟 | 記請假 → 系統要求（或暗示）揀三種 disposition 之一 → 後續先安排補堂或改綁下期 |
| 預期 | 三種指令入帳不同；禁止只改紙不改帳 |
| 前線體感 | **變難（最大負荷）**——忙時三選一易錯；錯選比「紙缺人」更難查 |
| 含義 | UX 必須有常見預設＋人話文案，唔好丢會計詞 |

### S04：提早交費、多月後先上

| 項目 | 內容 |
| --- | --- |
| 步驟 | 收款已入 → 本月堂次未宣告 → 點名紙無名 → 家長施壓 |
| 預期 | 系統正確拒絕「有錢＝自動出名」 |
| 前線體感 | **櫃枱吵、紙上對**——加名若變重路徑，開堂前五分鐘掣肘；若太易 override，帳又散 |

### S05：轉科／等額互轉

| 項目 | 內容 |
| --- | --- |
| 步驟 | 中文上 2 堂後轉數學（金額相同）→ 權益轉移＋audit |
| 預期 | 唔走萬能總池；舊池收、新池開 |
| 前線體感 | **中等難、少見高代價**——無明確轉移入口就會捷徑加名／改報讀 |

### S06：暑期完 → 9 月正規班

| 項目 | 內容 |
| --- | --- |
| 步驟 | 暑期權益仍在 → 想出現在新正規點名紙 |
| 預期 | 系統擋界；正規補堂落 7–8 月仍耗正規池 |
| 前線體感 | **系統幫擋、櫃枱要解釋**——要有可講出口嘅拒絕理由 |

### S07：正規按月約 4 堂

| 項目 | 內容 |
| --- | --- |
| 步驟 | 月費收款後假設「之後連續四堂自動出名」；中間請假一星期再返 |
| 預期 | 收款節奏 ≠ 名單主鍵；請假後唔自動掛去「之後四堂」 |
| 前線體感 | **心態要改**——會覺得系統「唔聽話」，除非文案講明 |

### S08：連堂補回拆兩次「安排補堂」

| 項目 | 內容 |
| --- | --- |
| 發現 | B＋宣告**本身醫唔到**缺 `consecutive_group_id`、兩張點名紙 |
| 前線體感 | 與而家相同摩擦；屬並行資料／UX 債 |

### S09：多入口名單（班詳情／欠堂／提醒／點名）

| 項目 | 內容 |
| --- | --- |
| 發現 | 若只有點名紙改規則、其他仍日期推，前線見「呢度有、嗰度冇」 |
| 前線體感 | **過渡期高危**——信任崩、來回核對；可令日常短暫惡化於現況 |

## 4. 難度總表

| 工作 | 應用後 | 原因 |
| --- | --- | --- |
| 取消後用「安排補堂」 | 易 | 同直覺一致 |
| 用「新增排程」補取消堂 | 仍易踩雷 | 宣告唔跟 |
| 正常點名 | 易／不變 | 名單更穩 |
| 解釋「有錢但無名」 | 難 | 權益 vs 宣告兩層 |
| 請假（三選一） | 難 | 多一步決策 |
| 開堂前人手救場 | 中→難 | 加名變補帳 |
| 轉科／跨學年 | 中 | 要正規轉移／擋界 |
| 對帳「還有幾堂」 | 長期易 | 終於有真權益帳；初期要學睇 |

## 5. 綜合判斷

### 5.1 唔會難喺邊

- 跨期補回缺人（P0 觸發型）。
- 「安排補堂＝全員應跟」卻只有單堂改掛嘅結構落差——主路徑可對齊前線心態。

### 5.2 會難喺邊

- 請假／調堂／順延要分清楚。
- 提早交費唔等於今日紙。
- 救場加名變重、同家長解釋兩層帳。
- 過渡期多入口規則唔齊。

### 5.3 致命條件（落地失敗訊號）

1. 宣告**唔**跟「安排補堂」自動帶走原堂名單，要前線日日手補宣告。  
2. 點名／班詳情／欠堂／提醒規則唔齊上線。  
3. 請假三選一無預設、無短文案，逼前線估。  
4. 手動加名要麼太難（開堂救唔到）、要麼太易（帳再散）。

一句：**用正確模型換來更亂日常**，通常係宣告自動化同入口一致性失敗，而唔係 B 哲學本身錯。

## 6. 對定案／UX 的建議底線（非開工清單）

供產品拍板時對照；**不取代** backlog「待做」與會計另案。

1. **安排補堂＝預設帶走原堂宣告名單**（單堂與期數生同一套）。  
2. 請假三選一：**預設＋人話**（要補返／唔補扣堂／留去下期）。  
3. 點名紙旁可見：**權益餘額**與**今日點解有／冇**（一句）。  
4. 手動加名＝受控宣告＋必填原因；開堂緊急可快、但必入帳。  
5. 「新增排程」補取消堂：黃橫幅／攔截，引導返「安排補堂」。  
6. 班詳情、欠堂、提醒與點名紙同一規則，一齊上線或明確標「未對齊」。  
7. 連堂補回拆紙問題並行處理，唔好假設權益模型會順便醫好。

## 7. 研究限制

- 純推演，無真實用戶觀察或可用性測試。  
- 假設暫定 B＋宣告最終拍板；若改採純 A 或長期 C，前線負荷曲線會不同（純 A：改預排重掛負擔高；長期 C：洞會再出）。  
- 會計口徑未定對前線間接影響（報表對唔上時會回頭問行政），本次未展開。
