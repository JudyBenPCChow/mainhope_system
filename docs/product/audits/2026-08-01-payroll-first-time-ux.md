# 計糧系統：首次使用 UX 審計（Cody 視角）

> 日期：2026-08-01  
> 對象：`mainhope-payroll-ui-sandbox`（更新後版本）  
> 方法：模擬 Cody 在無培訓、無指導下首次打開系統審計 7 月糧單  
> 原則：**不重複之前審查已指出的問題**（如 audit gaps、UX review 等），純以新手視角出發

---

## 核心發現：Cody 面對的不是一個「工具」，是一面「牆」

現在的原型功能極強、證據鏈極深。但對一個沒用過的人來說，他打開 system 的第一感覺不是「我可以開始審計了」，而是「這些是什麼？」。

以下不是 137 項清單，而是**按 Cody 的實際操作順序**組織的關鍵障礙。

---

## 1. 打開系統的前 10 秒 — 信任危機

Cody 打開頁面，視線由上而下掃過：

```
🔶 計糧 UI 沙盒（審計證據鏈 mock）
   版本／截止、母名單、$0 人、跨模式、逐學生 HC、原價時點、
   Cody 職責分離、已審審計、重算 diff、管理層抽查。不連 Supabase。

   預覽身份（非正式角色）
   [財務 — 計糧工作台 ▾]

   財務（Cody）可：審閱齊備度、逐人核對明細、處理異常、申請人手調整、
   申報 Cody 工時、排除後提交全月／單人送核。財務不可自行結算。
```

Cody 的即時反應：

| 他看到的 | 他的感受 |
|---|---|
| 「沙盒」「mock」「不連 Supabase」 | 這是假的，我在用測試版？ |
| 「非正式角色」 | 我的身份不是真的 |
| 一串英中混雜術語（HC、diff、$0人） | 這些是什麼？我需要懂嗎？ |
| 角色選擇器在他還沒做任何事之前就出現 | 我要選什麼？選錯會怎樣？ |

**核心問題**：系統的第一印象不是「我會幫你完成計糧審計」，而是「這是開發中的測試環境」。這在正式上線前必須替換成真正的 onboarding 體驗。

---

## 2. 進入工作台後 — 「我該做什麼？」

Cody 選了「財務」角色後，看到財務工作台。頁面標題是「計糧工作台」，下面是：

- 一個版本欄（資料截至…計算版本…）
- 一個「齊備度」區塊
- 四個數字卡片（未審批、已審批、異常、已送核）
- 一個異常列表
- 一列篩選按鈕（全部、未審、已審、異常、代堂、分成、HC）
- 一個教師名單（左欄）+ 空白右欄寫著「喺名單揀一位同事，睇計薪細節」

**核心問題**：沒有任何東西告訴 Cody **第一步該做什麼**。四個步驟（檢查齊備→審核教師→處理異常→提交）完全隱含在版面排序中，沒有 wizard、沒有進度條、沒有「從這裡開始」的提示。

Cody 的困惑：
- 「齊備度」是什麼？我需要處理它嗎？還是看看就好？
- 我應該先點教師名單的人嗎？哪一個？
- 為什麼 Billy Shek 排在最前面（因為有異常），而不是按薪酬高低排？
- 右欄寫著「喺名單揀一位同事」— 但 15 個人，我先揀誰？

---

## 3. 術語障礙 — Cody 沒上過明學內部培訓

以下詞彙在整個界面中**從未被定義**，但反覆出現：

| 術語 | 出現次數 | Cody 可能的誤解 |
|---|---|---|
| HC | 到處（篩選、表頭、LessonCard） | 「Health Check?」「Head Count?」 |
| 扣堂 | 表頭、摘要、LessonCard | 「扣」有負面意味 — 是罰錢？還是扣薪？ |
| 齊備度 | section 標題 | 沒聽過這個詞，是「準備好了沒」的意思？ |
| 母名單 | 齊備度內 | 為什麼叫「母」名單？和教師名單有什麼不同？ |
| 硬阻擋 | 摘要卡片 | 聽起來很嚴重但什麼意思？可以繞過嗎？ |
| 分成池 | SplitAuditPanel | 「池」是 literal pool？誰的錢放進誰的池？ |
| 代入／代出 | LessonCard tags | 誰代誰？方向性不清 |
| 1on1 → 3HC | 規則文檔有但 UI 沒解釋 | 為什麼 1 個學生算 3 個人頭？這是 bug 嗎？ |

**核心問題**：界面假設使用者已熟讀計糧指南。實際上 Cody 可能讀過一次，但不可能記住所有術語。每個術語首次出現時應有 inline 說明。

---

## 4. 互動的「隱形」問題

### 4.1 可點擊的東西看不出來

- 四個摘要卡片（未審批、已審批…）是 button，但看起來像 static card。沒有 hover 效果、沒有「點此篩選」文字
- 教師名單每一行有三個可點區域（選教師、標已審、排除 checkbox），Cody 容易點錯
- 「已審/未審」tag 點擊會 toggle 狀態，但 hover 才看到 tooltip 解釋。手機上完全看不見

### 4.2 破壞性操作沒有確認

- 切換月份 → 所有審核狀態**靜默清零**，沒有警告
- 點擊「重算」→ 立即重置所有人審核狀態，沒有「確定要重算嗎？」
- 管理層點「核實並結算」→ 直接凍結，沒有確認對話框

### 4.3 提交 checklist 是法律文件，不是 UI

```
☐ 已核對全部教師的逐節計薪明細（或已排除者）
☐ 已確認分成制原價池（Mark Yu、Christine Fan）
☐ 已確認代堂歸屬（Liam ↔ Kenneth）
☐ 已確認 Cody 工時申報／排除狀態
☐ 已確認 MPF（Mark、Christine、Sophie、Katie）
☐ 已知悉已排除項目將由 Mark Yu 跟進

☐ 本人（Cody Cheong）確認以上項目已如實核對；如有遺漏願承擔責任。
```

問題：
- 系統**已經知道**哪些老師已審、哪些還沒 — 為什麼要人手勾？
- 最後一行是法律免責聲明的語氣，不是 UI 確認
- disabled 時不告訴 Cody 漏了哪幾項 — 他要自己掃 6 個 checkbox

### 4.4 「查證排程／點名表」是死胡同

每節 LessonCard 有「查證排程／點名表」按鈕，點開後顯示 mock path（`/Schedule/sched-id`），不是真實連結。Cody 點進去發現無法真正查證，會失去對系統的信任。

---

## 5. 資訊優先序 — 最重要的東西最不明顯

### 5.1 沙盒 banner 是全頁最顯眼的元素

黃橙底色、置頂 — 但它是最不應該搶注意力的一行字。

### 5.2 總薪酬在頂部，但「怎麼算出這個數」要 scroll 很久

Cody 點 Mark Yu，右欄頂部看到 $33,600。但要理解這數字從哪來，他要 scroll 過：
- SalaryEvidencePanel（如果是固定月薪才有）
- ModeStreamsPanel（如果是跨模式才有）
- SplitAuditPanel（分成明細）
- TeacherLessonStats（逐節表）
- TeacherPayFooter（MPF + 上月比較）

五個面板，各自獨立。沒有一個「一頁 summary」把 $33,600 的來源一次展示。

### 5.3 齊備度有「硬」和「軟」之分，但視覺上沒區別

點名不齊 → 硬阻擋（不能提交）
代堂待核 → 軟提醒（可以提交）

但兩者在齊備度區塊的視覺權重完全相同。Cody 不知道哪個必須處理、哪個可以跳過。

---

## 6. 管理層視角的獨特問題

Cody 提交後，Mark 打開管理層 view。他的困惑：

- 「為什麼有人是單人送核、有人要等全月提交？」— 沒有解釋兩種機制的差別
- 「強制抽查」三項 — 他可以全勾但不展開任何明細。系統不檢查他有沒有真的看
- Cody WFH 核准區塊寫著「確認時數」，但 input field 可以改數字 — 這是確認還是修改？
- 「收下此人」— 這按鈕文字在 payroll 語境中很奇怪（「收下」像收快遞，不像核准薪酬）

---

## 7. 改善建議（按 Cody 的體驗順序）

### 7.1 第一印象（前 10 秒）

| 問題 | 建議 |
|---|---|
| 沙盒 banner 搶注意力 | 正式版移除；保留一個小標籤「v3」或「示範數據」在角落 |
| 角色選擇器寫「非正式角色」 | 移除「非正式」字眼；首次登入根據真實角色自動進入對應 view |
| 術語轟炸 | 移除 banner 中的術語清單；換成一句人話：「此頁面協助你審核及提交每月教師薪酬」 |

### 7.2 進入工作台（前 60 秒）

| 問題 | 建議 |
|---|---|
| 無「第一步」提示 | 右欄空白狀態不要只寫「揀一位同事」，要引導流程：「1. 先檢查上方齊備度 → 2. 點教師名單開始審核 → 3. 處理異常 → 4. 提交」 |
| 術語無解釋 | 每個術語首次出現時附 `?` icon，hover 顯示一句解釋（例如 HC：「Head Count，計薪學生人次」） |
| 教師名單排列邏輯不明 | 名單上方加一行說明：「按異常優先排列；紅色邊框 = 有異常未審」 |

### 7.3 互動改善

| 問題 | 建議 |
|---|---|
| 卡片不似可點擊 | SummaryTile 加 hover 效果 + cursor pointer + 「點此篩選」文字 |
| 切換月份／重算無確認 | 加入確認 dialog：「切換月份將清除所有審核進度，確定嗎？」 |
| 提交 checklist 太 intimidating | 系統自動檢測已完成的項目（例如已審 15/15 就自動勾第一項）；只要求勾「無法自動驗證」的項目；法律聲明改為中性語氣：「我已覆核以上項目，並對提交的數字負責」 |
| 「查證」按鈕是死胡同 | 正式版須連結到真實 Schedule/Attendance 頁面 |

### 7.4 資訊架構

| 問題 | 建議 |
|---|---|
| 總金額與 breakdown 分離 | 右欄頂部加一個「薪酬來源摘要」小區塊，一行顯示各來源金額（例如 Mark：個人 $X + 數學 pool $Y = $33,600），點擊跳至對應 panel |
| 齊備度不分硬軟 | 硬阻擋項目標示紅色邊框＋「必須處理」；軟提醒用黃色＋「建議處理」 |
| LessonCard 資訊過載 | 預設只顯示：日期、HC、金額、公式。其餘（學生名單、原價明細、事件時間線）收合在「顯示完整證據鏈」toggle 內 |

### 7.5 管理層

| 問題 | 建議 |
|---|---|
| 抽查可跳過 | 抽查項必須展開該教師的明細（至少 scroll 到 SplitAuditPanel）才算完成；單純勾 checkbox 不算 |
| 「收下此人」命名 | 改為「確認此人無誤」或「核實」 |
| Cody 工時確認 vs 修改 | 分兩個 input：一個顯示「財務申報時數」（唯讀），一個「管理層確認時數」（可編輯）。標籤清楚區分 |
| 結算無確認 | 加入確認 dialog，列明「結算後此月數據不可再修改」 |

---

## 總結

這個原型在**功能深度**上是出色的。但在**首次使用體驗**上，它假設使用者：
- 已熟讀計糧指南
- 理解所有內部術語
- 知道四步工作流程
- 能辨認哪些 UI 元素可互動
- 不會誤觸破壞性操作

這五個假設對於第一次打開系統的 Cody 全部不成立。改善重點不是加更多功能，而是加**引導、解釋、確認閘門**。每一項改善都是小改動（一句文案、一個 icon、一個 dialog），但疊加起來會把「一面牆」變成「一條路」。
