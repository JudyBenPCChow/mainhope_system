# 請假與補堂：連堂單項處理

> 狀態：**目前已完成並上線**（行政／接待可用）。  
> 入口：請假管理 `/LeaveManagement`、學生詳情請假、前台指引「請假」步驟、進行點名 `/Attendance`、排程點名紙。  
> 扣堂規則：[`ATTENDANCE_BILLING.md`](../ATTENDANCE_BILLING.md)

本文說明**連堂只欠／只補一堂**的正確做法，避免把補堂寫進連堂整組而多計一堂。

---

## 1. 要達成什麼

| 目標 | 做法 |
| --- | --- |
| 正確記錄補堂日期與時間 | 調堂時綁定學生實際坐入的那一節（第 1 或第 2 節） |
| 老師可以點到名 | 該生出現在該班當日點名紙 |
| 不會因連堂多計一堂 | 系統只為所綁那一節寫出席，**只計 1 堂** |

學生**可以**實體坐在連堂的第一節或第二節補堂；重點是系統要綁對那一節，而不是整組兩節一併點。

---

## 2. 請假（欠堂）

### 2.1 連堂請假範圍

選到連堂排程時，可選：

| 選項 | 結果 |
| --- | --- |
| **連堂兩節一併請假**（預設） | 建兩筆請假；最多欠補 2 堂 |
| **只請本節** | 只建一筆；欠補 **1** 堂 |

選單會標「連堂·第 N 節」，方便分辨。

### 2.2 前台指引精靈

勾選未來排程時：

- **只勾連堂其中一節** → 只請該節  
- **兩節都勾** → 整組請假  

畫面有提示，請依實際欠堂勾選。

### 2.3 尚未支援

**原班生**同一日「第 1 節請假、第 2 節照常出席」的分節點名**仍未支援**。原班連堂點名仍為整組同一狀態。若實務常見，須另開需求。

---

## 3. 安排補堂（調堂）

1. 在請假管理詳情／列表選「調堂」或「選擇調堂日」，或新增請假時直接選調堂。  
2. 補堂候選會標 **「連堂第 N 節」**——請選學生**實際坐入**的那一節。  
3. 欠 2 堂時：請分兩筆各約一節（或兩個單堂日）；勿以為約一節就補完兩堂。  
4. 連堂整組請假時若一併選調堂：系統只把調堂套在**第一筆**，其餘先「待安排」，需再跟進。

---

## 4. 點名

| 學生類型 | 點名紙 | 計堂 |
| --- | --- | --- |
| 原班連堂生 | 有；兩節一併 | **2** |
| 單項補堂生（只綁一節） | 有；標「補堂·僅第 N 節」 | **1** |

- 儲存後若曾誤寫成兩節，重存點名會清掉多餘那一節。  
- WhatsApp 課堂提醒對單項補堂生只顯示**所綁那一節**時間，不會寫成「兩堂連堂」。

---

## 5. 常見錯誤

| 錯誤 | 後果 | 正確做法 |
| --- | --- | --- |
| 只欠 1 堂卻選「兩節一併請假」 | 待補變成 2 | 選「只請本節」 |
| 調堂選錯節（坐第 1 卻綁第 2） | 日時不對 | 改綁正確那一節後再點名 |
| 欠 2 只約 1 節就當完成 | 另一筆仍待補 | 第二筆另約 |
| 期望原班半節到、半節假 | 系統記唔到 | 暫用備註／整組處理，或另議分節點名 |

## 6. 取消請假／清調堂（與出席）

> A1 已上線行為。詳見方案 [`../plans/2026-07-31-lifecycle-orphans.md`](../plans/2026-07-31-lifecycle-orphans.md)。

### 6.1 本版覆蓋／未覆蓋

| 覆蓋（A1＋A2＋O3＋O4；主題已結案） | 未納本期（另開） |
| --- | --- |
| 刪請假、清／改 `makeup_schedule_id`（含詳情／補課安排改離調堂） | 出席「資格已結束」可見性標籤（O0）；健康檢查（O5） |
| 列表「學費處理」改離調堂（減收／轉結餘／錄影）＋强制清 schedule／對齊 type | |
| 連堂 peers＋仍應到則保留；otherMakeup 唔保留已取消／完成堂 | |
| 三路 Confirm：預設一併刪；保留需二次確認 | |
| 試堂取消／刪／改期：强制一併刪出席（無保留） | |
| 點名存檔重拉名冊＋`saveAttendanceStatus` 拒寫名冊外 | |
| **admin／外星人單列刪出席**（學生詳情主入口；出席紀錄輔）＋audit | |
| **軟取消排程**：調堂改回待安排；未結案試堂一併取消；已有出席 Confirm（預設保留） | |
| **退讀／手誤清報讀**：掃本班出席＋Confirm（退讀預設保留；purge 預設刪） | |

計費定義仍只看出席 status 白名單，不看資格。

### 6.2 行政操作

1. 刪請假或清／改調堂時，若掃描到**可刪**補堂出席 → Confirm。  
2. 列表改「學費處理」離調堂且仍有調堂排程 → 同上 Confirm；成功後會清 `makeup_schedule_id`／date。  
3. **預設＝一併刪**（計費列會影響已上堂數；可能要輸入姓氏）。  
4. **保留出席**須再確認一次；取消第二次＝整筆中止。保留後點名紙可無名但已上堂數仍計。  
5. 仍有報讀／其他調堂應到的堂次**不會**進可刪列。

### 6.3 老師請假精靈 SOP

老師精靈清調堂時若該生補堂已點名 → **失敗**（提示含學生姓名＋請假 id）。  
流程：老師通知行政 → 行政在 `/LeaveManagement` 三路 Confirm 處理 → 完成後老師可再跑精靈。  
老師**不可**自行刪計費出席。

### 6.4 操作紀律

- 點名已有寫回防護（存檔前重拉名冊；名冊外拒絕 upsert）。仍建議先完成／關閉點名紙再大改調堂，減少略過提示。  
- **勿硬刪已點名排程**；應軟取消。  
- 歷史孤兒清庫見 [`LIFECYCLE_ORPHAN_CLEANUP_RUNBOOK.md`](./LIFECYCLE_ORPHAN_CLEANUP_RUNBOOK.md)。
- 試堂：要留出席就唔好取消／刪／改期（無「保留出席」選項）。
