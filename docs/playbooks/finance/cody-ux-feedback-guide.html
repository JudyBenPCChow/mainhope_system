以用戶感受描述系統問題
（給 Cody，供工程改善畫面與操作）

目的：當你覺得系統難用、易錯、看不懂，或懷疑算出錯時，用「實際使用感受」寫下來，讓工程人員能改善畫面與操作流程。

重點：寫你看到甚麼、做了甚麼、以為會怎樣、實際怎樣、令你擔心甚麼。不必寫程式術語。

何時應該寫

  1. 找不到該去哪一頁核對。
  2. 同一數字在不同地方不一致，或你不知道該信哪一個。
  3. 步驟太多、容易漏做（例如未點名仍好像可以往下走）。
  4. 用詞含糊（例如「狀態」「提交」「結算」分不清意思）。
  5. 出錯後不知道下一步，或怕按錯會不可挽回。
  6. 你手算正確，但畫面總數對不上，又找不到明細解釋差異。

撰寫模板（每次一則問題用一份）

【系統使用感受回報】 回報人：Cody 日期： 相關月份／同事：（如適用） 相關頁面：（你當時停留的畫面名稱，例如「計糧」「出席紀錄」「排程管理」） 一、我想完成甚麼 （用一句話：例如「核對某老師七月有沒有漏點名，再確認他應收金額」） 二、我實際做了甚麼（按時間順序） 1. 2. 3. 三、我當時看到甚麼 - 畫面上的關鍵數字／狀態／按鈕名稱： - 有沒有警告或提示： - 有沒有覺得「好像可以繼續」但其實資料未齊： 四、我預期會怎樣 （例如：「未點名應該不能提交」「點開老師應該看到每一節怎麼算出來」） 五、實際怎樣 （與預期不同的地方，愈具體愈好） 六、這對我造成甚麼影響（選適用項，可多選） □ 怕算錯糧 □ 要花很長時間人手重算 □ 不知道該信系統還是信自己 □ 需要反复問人 □ 可能按錯又無法回頭 □ 其他： 七、嚴重程度（選一） □ 阻礙出糧（現在不能安心做下去） □ 容易出錯（做得下去，但不放心） □ 麻煩但可繞過（有替代做法） □ 建議優化（不急，但長期會更好） 八、若可以改善，我希望變成 （用「希望畫面可以……」來寫，例如： 「希望每位老師下面可以直接展開：日期、班別、人頭、該節金額、合計」 「希望未點名的課堂用紅色列表，並清楚寫不能提交的原因」） 九、附件 - 螢幕截圖（遮蓋敏感個資後） - 你的手算過程或核對表相關列

寫得好的例子（可模仿）

例子 A：怕漏點名仍被計入或漏計 我想確認七月是否還有未點名課堂。我在出席紀錄逐班翻，很花時間，也不確定有沒有漏網。計糧頁有總金額，但我看不到「還有多少節未點名」的清單。我預期未完成點名時系統會清楚擋住，並告訴我是哪些班、哪一天。現在我只能靠自己另做清單，很怕漏了還照交 Mark。
例子 B：看不懂總數從何而來 我核對某兼職老師，手算是 $2,140，畫面上是 $2,280。我點進詳情後仍看不到是哪一節多了、人頭如何計。我無法判斷是我漏了一節，還是系統多算。希望每一節都顯示：日期、是否代堂、人頭、單節金額，並加總成與總數一致的明細。
例子 C：用詞令流程不安心 我看到「審閱」「提交」「結算」等字，但不確定我按了之後 Mark 還可不可以改、會不會鎖定。我擔心按錯就無法回頭。希望按鈕附近用一句白話說明：按了之後誰會收到、還可不可以退回。

寫法注意（請遵守）

  1. 一次聚焦一件事；不要把五個問題寫成一則。
  2. 先寫事實與感受，再寫希望；不要一開始就猜「是不是程式壞了」。
  3. 避免空泛形容（例如只寫「不好用」「很亂」）；改寫成「我找不到……」「我分不清……」。
  4. 尽量附截圖與月份，方便對照。
  5. 金錢差異必須同時附你的手算，否則工程難以重現。
  6. 若同時懷疑「同事點名錯了」與「系統算錯了」，請分開兩則：一則給營運跟進資料，一則給工程改善畫面。

給工程人員時的短封面（可放在多則回報前面）

本批為財務使用感受回報，目的是改善計糧／點名相關畫面與操作， 令複核人員可以： 1）先確認課堂與點名事實； 2）自行看懂每一節如何加總； 3）在資料未齊時被清楚提醒，而不是只看到一個總數。 請按「阻礙出糧 → 容易出錯 → 可繞過 → 建議優化」排序處理。
