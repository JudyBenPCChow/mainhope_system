## 1. 要解決的問題



### 1.1 根因

收費偏「堂次數量」直覺；點名長期用**日曆推期數**或半套單堂改掛。沒有統一「學生還有幾堂」權益帳，改期／跨期補回時點名紙會缺人。

前線約束：

> 收了幾堂錢，就應該來幾堂；改期不改「有沒有份」。



### 1.2 必須解決


| #   | 問題                           | 狀態                  |
| --- | ---------------------------- | ------------------- |
| P1  | 跨期／改期後點名缺人                   | 模型已定；`2627` live 未驗 |
| P2  | 統一權益池＋命名空間                   | Schema 已上；支付抬池未接    |
| P3  | 到課宣告＝行政名單（欠費可上紙）             | `2627` 已接           |
| P4  | 點名消耗／返還（可負池）                 | 薄做已上；§4.5           |
| P5  | 入口勿日期推期數                     | 主要入口已收斂             |
| P6  | 手動加名走補宣告                     | UI 未做               |
| P7  | 學年邊界                         | 規則已寫                |
| P8  | 學費→池；建議；廢月費／credit；轉科搬堂；請假可見 | **§4 大半已齊；§6 餘確認題** |


不在本階段：會計收入認列；常規退費產品化。

### 1.3 約束情境

- 交四堂中間請假 → 不可自動掛之後連續四堂
- 提早繳費 → 紙靠宣告，唔靠餘額
- 轉科 → 搬堂數（§4.8）
- 欠費可上紙；池跨月滾；唔強制每月交
- **行政請假頁＋老師點名紙**都要能見到「呢日唔嚟、唔使補」

## 4. 已拍板產品句（工程必須跟）



### 4.1–4.3 池真源／廢月費／與排程脫鈎

- 學費入池；雜費不入；確認收款自動 top_up。
- 繳費頁為主；刪月費獨立產品路徑。
- 報讀空池；加排程不抬池。



### 4.4 繳費建議

`建議 = max(0, 該月該科會扣堂排程單位 − remaining)`  
可為 0、可多交、跨月滾；`remaining` 負則建議追回。

### 4.5 負池

容許負；唔另建還債流程；繳費頁顯示欠費並 top_up。

### 4.6 建議基數

計入：正常／補回／加堂（預期會扣堂）。  
唔計：請假後不扣堂、老師取消。  
範圍：同一池命名空間。

### 4.7 交費前／後請假處置

交費前：可唔上該堂、唔交、唔補（唔入建議基數）。  
交費後：唔改收據／已 top_up；只有「有補堂／錄影 zoom／不補順延／no show 當扣堂」四種（見前表）。  
可見性要求見 §4.9／§5.5。

### 4.8 轉科搬堂

常規不退費；前台頁按**堂數**搬池；特殊退費非正式路徑。

### 4.9 請假可見（硬性）

- 交費**後**請假：點名紙**見名**＋預填事假／病假。
- 交費**前**唔上：行政請假頁**同**老師點名紙都要見到「唔嚟、唔使補」（流程採 §5.5 建議；§6 G1 請確認）。



### 4.10 轉結餘

Prod 0 筆；停新增 credit 寫入。

### 4.11 罰款／入池口徑（F3 已答部份）

- **遲交罰款：不入池。**
- **入池只睇學費行** `lesson_count`（金額／優惠只影響錢，唔另計公式）。



### 4.12 推得


| 項       | 結論              |
| ------- | --------------- |
| Cutover | 已付−已消耗；其後可因點名變負 |
| 建宣告     | 不檢查餘額           |
| 作廢      | 按錯單類型，見 §6 G2   |

## 5. 待做工程方案



### 5.1 Live 驗收閘

有 `2627` 班後全鏈＋負池＋shadow。

### 5.2 支付 → 池

- 確認收款：學費 `lesson_count` → top_up（冪等）。
- 罰款／雜費永不 top_up。
- 空池＋宣告；扣堂可負；UI 欠費。
- 作廢：§6 G2 定案後實作。



### 5.3 繳費建議（`/Payments`）

實作 §4.4／§4.6；建議 0 顯示「本月唔使交」；已確認單唔因改假自動改。

### 5.4 廢月費＋停 credit

退役 `MonthlyTuition*`；停 `tuition_credit_entries` insert；改文案；回寫 dead-surface-cleanup。

### 5.5 請假「唔嚟唔補」——工程建議流程（等 G1 確認）

**目標（你已定）：** 行政請假頁＋老師點名紙都清楚見到「呢日唔上、唔使補」；流程要簡單。

**建議：沿用同一套請假紀錄，唔開第二套入口。**

```text
行政喺請假頁選學生＋原定排程
  → 建立／更新 leave 紀錄
  → 處置預設：「唔上／唔補」（交費前）或既有事假／病假＋補堂選項（交費後）
  → 點名紙：保留名＋預填不扣堂狀態（事假／病假／或同等「請假唔補」標籤）
  → 繳費建議：該堂唔入「會扣堂」基數
  → 唔自動建補回堂
```

**點解唔另造「一鍵唔叫請假」：**  
另詞易同病假／已購堂請假撈亂；老師要學兩套紙上意思。同一請假頁、同一紙上預填，行政只多填「有無補堂＝無」。

**交費前 vs 後差別只係預設同可否改收據（後者唔改），入口同一個。**

**老師所見：** 名單有人；狀態已係不扣堂；唔使猜。  
**行政所見：** 請假列表有呢日、標明唔補。

若 G1 確認，工程照此收斂；唔再分 A／B／C 平行宇宙。

### 5.6 試堂／人頭——工程建議（等 G3 確認）

**已定方向：** 試堂生要上點名紙；收費可正價／半價／免費；有時**唔收學生錢、亦唔計老師人頭**，但仍要上紙知邊個嚟。

**建議拆三條獨立軸（互唔綁死）：**


| 軸        | 做法                                                                                    |
| -------- | ------------------------------------------------------------------------------------- |
| **名單**   | 試堂繼續 **union 上點名紙**（有宣告或試堂掛勾即可）；**不**靠權益池                                             |
| **權益池**  | 試堂**預設不鑄池**。若收「可扣堂學費」並填學費 `lesson_count` → 跟通用規則 top_up（轉正前都可）；純觀摩／$0 且堂數 0 → 唔入池     |
| **老師人頭** | 試堂列加旗標（名待定，如 `counts_for_teacher_headcount`）：預設 `true`；「免費觀摩、唔計人工」＝`false`。與收唔收學生錢分開勾 |


**贈堂：** 唔另造「贈堂事件」。要加池就開學費收據（可 $0／優惠價）＋填 `lesson_count`——同 §4.11 一致、最少特例。

### 5.7 轉科搬堂頁

選來源池→目標池、搬堂數、稽核、宣告重掛。

### 5.8 安全網／日落

手動加名 UI；`26SM` 廢 `makeup_of`。

### 5.9 不做

收入認列；欠費門禁；計糧讀池；常規退費 UI。

### G2 — 作廢學費單：按「錯咗咩」揀行為（原 F2）

你要求先列清「收據錯」類型。下列係行政實務上常見、同系統要對應嘅錯。請每類揀：**拒作廢直至先處理點名／池**（穩）／**准作廢只 clawback 未消耗堂**／**可改欄唔作廢**／**其他（請寫）**。  
  
回覆︰  
目前我們系統單據作廢，有沒有一個程序？如要輸入密碼或manager批准？  
如開單後30分鐘內，我同意可以無條件作廢（因為30分鐘，我相信仍未構成任何點名扣堂）  
如果已超出30分鐘，要有一個嚴謹的作廢程序。除了是考慮權益池正確入帳外，亦是避免員工利用漏洞偷錢，或誤刪造成吷重影響。（當然由於收據中，權益池增加是涉及堂數而不是收款金額，所以事實上本議題與金額無直接關系）


| 錯單類型               | 例子                       | 對池／點名影響           | 建議預設（可改）                                                |
| ------------------ | ------------------------ | ----------------- | ------------------------------------------------------- |
| **G2a 堂數填錯**       | 應收 4 填咗 6 → 池多 2         | 若已上過堂，多出嘅可能未耗或已耗  | 未上課：作廢重開或改單；已耗部分 → 傾向 **拒整單作廢** 或只 clawback 未耗          |
