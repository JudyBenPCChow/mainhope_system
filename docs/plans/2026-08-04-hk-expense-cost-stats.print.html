0. 目標

為 HK 建立公司開支日記帳＋月度成本儀表板：

  • 入帳（對齊 Excel 月表欄位）
  • 規則自動建議分類帳＋人手覆核
  • 儀表板睇已確認總開支／分類趨勢；待覆核另欄顯示

明確不是：員工績效、計糧引擎、正式損益、CN 帳、收據上傳、複式記帳。

1. 決策鎖定

項目決定
範圍只 HK；唔做 CN 檔／收據／OCR
角色manager／alien 可見可入；admin／teacher 無側欄入口
分類規則建議＋人手覆核；pending_review 不入分類彙總
與 StaffPerformance不取代、不做自動對賬
與計糧獨立；日記帳薪金列＝出糧紀錄語意，非正式應計

歷史匯入APR–JUL → pending_review，不自動 confirmed

2. 最低安全組（對抗模擬必做）

以下由三角度模擬（營運／RLS／跨模組）抽出，實作時必須納入，唔算可選。

2.1 RLS／審計

  1. 唔用 is_mgmt_staff()（會令 admin API 讀寫開支）。三表 RLS：

current_app_role() in ('manager', 'alien')（SELECT／INSERT／UPDATE）。

  1. 禁硬刪（無 DELETE policy）；加 voided_at／void_reason／voided_by_label；儀表板只計 voided_at is null。
  2. confirmed 鎖定：不可直接改 amount_hkd／spent_on／ledger_account_id；改類須先回 pending_review（trigger 或 service 分函式 confirmEntry／reopenForRecategorize）。
  3. 規則表／ledger 寫入：seed 後，expense_category_rules 寫入限 alien（manager 只讀）；ledger accounts 同期（避免規則被污染）。
  4. FK：ledger_account_id → ON DELETE RESTRICT；確認時 account 須 active。

2.2 建議規則優先序

Suggest 定序：priority DESC，同優先則 length(pattern) DESC，再 id。

優先（高→低）pattern 例建議科目
高按金唔建議租金；建議「費用 - 其他費用」或留空＋提示「或非費用／待拆」
高清潔人工／清潔費用 - 清潔費
高前台／行政成本 - 其他直接成本（字典暫無前台科目）
高mpf／強積金成本 - 導師薪金(強積金）
中電費費用 - 電費
中租金／管理費（且無按金）費用 - 租金及管理費
中寬頻／電話／上網費用 - 上網或電話費
中Adobe／Zoom／Microsoft／Cursor／Canon／Printer費用 - 牌照及營運相關 或 其他費用
低泛用 人工／薪唔自動分科；建議留空或只提示「導師薪金類、請人手揀科」→ 多半仍 pending_review

禁止：低優先「人工」蓋過「清潔人工」「前台」。

2.3 儀表板防呆／文案

  • 頁首固定：

「HK 公司開支日記帳（現金／付款日）。唔係員工績效、唔係計糧、唔係損益表。」

次行：「與員工績效人工、計糧結果不做自動對賬；Excel 可並行，以本頁已確認分類為彙總來源。」

  • KPI 拆卡（禁止「毛利／淨利／盈虧」字眼）：

- 已確認開支合計

- 直接／間接（僅 confirmed）

- 待覆核金額／筆數（不入分類）

  • 待覆核佔當月總流出 > 30% → 警告：「分類趨勢未可靠」。
  • 月份篩選旁：「統計月＝開支日期（付款／入帳日），唔係計糧所屬月。例：4 月付 3 月薪 → 計入 4 月。」
  • 分類圖／長條只標「已確認」。

2.4 匯入冪等

  • import_batch_id（nullable）＋ source_key（如 HK|2026-04|rowHash）UNIQUE（允許 null source_key 給人手入帳）。
  • 重跑唔重複列；一律 pending_review。

3. 資料模型

expense_ledger_accounts
  id uuid PK
  code text unique          -- 穩定碼，供 seed／規則引用
  label text                -- 顯示名（對齊 Excel 清單名稱）
  account_group text        -- 'direct' | 'overhead'
  subject text null         -- 中文／英文／數學／理科／功輔 等
  sort_order int
  active boolean default true
  region text not null default 'HK' check (region = 'HK')

expense_category_rules
  id uuid PK
  pattern text not null     -- substring；匹配時 lower()
  ledger_account_id uuid null FK → accounts (RESTRICT)
    -- null = 規則命中但故意不自動填科目（例如泛用「人工」）
  force_pending boolean default false  -- true：只提示、suggested 可空
  hint text null            -- UI 提示（按金／請人手揀科）
  priority int not null default 100
  active boolean default true

expense_entries
  id uuid PK
  region text not null default 'HK' check (region = 'HK')
  spent_on date not null
  title text not null
  amount_hkd numeric(12,2) not null check (amount_hkd <> 0)
  pay_method text not null
    -- 銀行 | 現金 | CASH BOX | 余sir | 內地還款 | 其他
  owner_label text not null default ''
  receipt_label text null
  ledger_account_id uuid null FK → accounts (RESTRICT)
  ledger_status text not null
    check (ledger_status in ('pending_review', 'confirmed'))
  suggested_ledger_account_id uuid null FK
  suggestion_rule_id uuid null FK → rules (SET NULL)
  suggestion_hint text null
  notes text null
  created_by_label text not null default ''
  import_batch_id text null
  source_key text null
  voided_at timestamptz null
  void_reason text null
  voided_by_label text null
  created_at / updated_at timestamptz

  unique (source_key) where source_key is not null
  -- confirmed 時 ledger_account_id 必須 not null（trigger 或 check 約束能表達則加）

Seed expense_ledger_accounts 對齊 Excel「清單名稱」（分科薪金／分科教材／強積金／間接費用等）。

本期不加「前台／行政」新科目（用「其他直接成本」＋規則）；若覆核體驗差再下一波加科。

4. 服務與純邏輯

路徑職責
src/lib/expenseCategorySuggest.ts純函式：title + rules → `{ accountId, ruleId, hint } \null`
src/services/expenseQueries.tslist ledgers／rules；CRUD entries；confirm／reopen／void；月彙總（硬編碼 confirmed + 未 void）
組件不直打 supabase.from

入帳流程：

  1. 填表 → suggest → 預填 suggested（可改）→ 存成 pending_review（即使已選科目，未按「確認」前仍 pending；或入帳時可選「儲存並確認」若已選科目）。
  2. 實作選擇（鎖定）：新建預設 pending_review；同頁提供「確認」／批量「確認建議」（須已有 ledger_account_id）。
  3. 批量確認：多選 pending 且已有科目者一次 confirmed。

6. 歷史匯入

一次性腳本或頁內「匯入批次」工具（alien／manager）：

  • 讀 HK Excel APR–JUL 月表（日期序列→date、項目、金額、付款方式、負責人、單據）
  • 寫入 expense_entries：source_key 冪等；跑 suggest；一律 pending_review
  • 回傳：新增／跳過（已存在）／失敗列數

腳本位置建議：scripts/import-hk-expenses-from-xlsx.mjs（或 src/services 內 import 函式＋UI 按鈕觸發已解析 JSON）。實作優先：service 函式接受已 parse 列＋CLI／一次性 node 腳本讀 xlsx。
