# 明學教育對抗性檢查

## 授權與限制

- 預設只在本機或明確指定的預覽環境執行；正式環境只做被動／唯讀驗證，除非使用者明確授權特定測試。
- 不掃描公共網絡、不猜測帳號或密碼、不繞過登入、不存取其他人的資料、不執行破壞性寫入。
- 用測試帳號與測試資料驗證；若沒有可用角色或測試環境，改做程式碼、migration 與政策靜態審查，並清楚標示限制。
- 前端隱藏、`localStorage.mgmt_role` 與資料庫 RLS 是不同防線；必須分開判斷。

## 執行流程

1. 讀取 `AGENTS.md`、相關服務查詢、頁面／元件、`supabase/migrations` 與直接相關的 RLS 文件或操作政策。
2. 先界定範圍、環境、可用測試角色、資料類別與不會觸發的動作。
3. 以安全方式檢查：
   - **授權邊界**：直接路由、被隱藏 CTA、服務層查詢範圍、角色切換，以及老師只應見自身資料的邊界。
   - **資料暴露**：列表、搜尋、錯誤訊息、下載／匯出、快取或 URL 是否帶出不應見的學生、付款或薪酬資料。
   - **輸入與狀態**：空值、非法日期、重複提交、並發重試、過期畫面、取消／撤銷與流程狀態轉換。
   - **完整性**：代堂不應改主責、點名／扣堂／繳費／學年等關鍵規則是否可被不當操作繞過。
4. 對每項發現給出可重現但不會洩露敏感資料的證據。把「已確認」與「僅靜態推測」分開。
5. 風險分級：Critical（可造成嚴重未授權存取或不可逆資料損失）、High、Medium、Low。每項說明受影響角色與資料。
6. 報告寫入 `docs/audits/YYYY-MM-DD-<scope>-adversarial.md`。只在確認有對應工程主題時，回寫該 backlog 分題；不要在稽核時自行修正產品。

## 報告格式

```markdown
# <範圍>：對抗性檢查

| 欄位 | 值 |
| --- | --- |
| 日期 | YYYY-MM-DD |
| 環境與授權 | 本機／預覽／正式唯讀；測試角色 |
| 方法 | 動態測試／靜態審查 |
| 結論 | 一句摘要 |

## 覆蓋範圍與限制
- 已測：
- 未測及原因：

## 發現
### High：<標題>
- 類別：授權／資料暴露／輸入／狀態完整性
- 確認程度：已確認／靜態推測
- 重現（不含敏感資料）：
- 影響：
- 修正方向：

## 已驗證防線
- <已確認的保護及其證據>
```

## 完成回覆

列出報告檔案、按風險分級的數量、已確認與未驗證的界線。Critical 或 High 發現必須在回覆最前面明確指出。
