# 明學教育營運巡檢

## 範圍與安全

- 預設檢查本機或指定的預覽環境；不得把測試資料寫入正式環境。
- 只用既有測試帳號、角色切換或明確授權的測試資料；不要把前端角色顯示當作資料庫授權證據。
- 未提供目標環境或可用測試角色時，先說明缺口並只做靜態流程審查。
- 不實際送出付款、通知、刪除、排班覆蓋或其他不可逆動作。

## 執行流程

1. 讀取 `AGENTS.md`，再讀與本次範圍直接相關的操作手冊、政策及 backlog 分題。
2. 明確列出本輪角色、環境、測試資料與情境；至少涵蓋一名老師及一名行政。沒有真實可用身份時，標示為「介面模擬」。
3. 依角色完成高頻任務，而非只巡覽畫面：
   - 老師：查看自己的排程、點名／代堂相關流程、查閱所需學生或班別資料。
   - 行政：查找學生／班別、處理排程或請假、查看所需收款／通知或待辦資訊。
   依本次變更及頁面可用功能調整任務，並記錄每一步的結果。
4. 量度可重現的等待：記錄載入、搜尋、儲存後回饋或路由切換的可見延遲；可用瀏覽器效能資料時附量測方式。沒有可靠量測時，只描述「主觀卡頓」，不得虛構毫秒數。
5. 檢查操作完成性：入口能否找到、資訊是否足夠、錯誤能否理解、成功後是否有回饋、返回後狀態是否一致、手機／窄視窗是否妨礙高頻步驟。
6. 依影響分級：P0（無法安全完成／資料風險）、P1（高頻阻塞或高誤操作風險）、P2（明顯效率問題）、P3（易用性改善）。
7. 把報告寫入 `docs/audits/YYYY-MM-DD-<scope>-operational-simulation.md`。只在發現對應未完成工作且有明確歸屬時，更新既有 backlog 分題；不要把稽核報告誤列為已完成工程。

## 報告格式

```markdown
# <範圍>：營運流程模擬

| 欄位 | 值 |
| --- | --- |
| 日期 | YYYY-MM-DD |
| 環境 | 本機／預覽／其他 |
| 角色與方式 | 老師：…；行政：…（真實測試／介面模擬） |
| 結論 | 可運作／有阻塞；一句摘要 |

## 情境與證據
### S01：<角色—任務>
- 步驟與結果：
- 時間或等待證據：

## 發現
### P1：<問題標題>
- 情境／重現步驟：
- 影響：
- 證據：
- 建議：

## 未能驗證
- <缺少的身份、資料或環境>
```

## 完成回覆

列出報告檔案、各優先級數量、不可驗證項目，以及有否更新 backlog。不要把介面角色檢查描述成 RLS 或真正授權測試。
