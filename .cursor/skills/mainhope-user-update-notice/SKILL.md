# 系統使用者更新公告

給**用系統的同事**看，不是給工程或下一個 agent。術語跟 `.cursor/rules/terminology.mdc`。

工程收尾、backlog、驗證紀錄用 `mainhope-release-handoff`；本 skill 只負責使用者文案。

## 先判斷格式

- **涉及日期、時間或班別**（新增／取消／改時段／改逢星期）→ 用下方「分列」格式。唔好寫成一段。
- **其餘**（畫面、流程、預設值）→ 用下方「一段」格式。

## 分列（日期／時間／班別）

標題一行，後接全形冒號「︰」。其後按老師或改動類型分段；每班一行，寫課程名稱及 course code、逢星期、時段。取消後改開嘅班，先寫原有再寫改為。末句使用方法。

例子格式如下︰

```
2627學年BAFS及M2科目更新︰

新增BAFS 班別（Rafael Ling）
1. 課程名稱及course code  逢星期五 19:00-20:15  
2. 課程名稱及course code  逢星期日 10:15-11:30

新增M2班別及取消英文班別（Cheryl Ng）
原有 課程名稱及course code  逢星期六10:15-11:30  即時取消，並改為
課程名稱及course code 逢星期六10:15-11:30 

以上修正可於班別頁查閱及進行報讀登記。
```

把「課程名稱及course code」換成畫面實際名稱（含年級）同 `course_code_full`。唔寫檔名、commit、測試、migration。

## 一段（畫面／流程）

```
<標題>︰<原有問題>，<改善方法>，<對使用者的具體影響>。<使用方法>。
```

1. **標題**：畫面或功能＋改了什麼（例如「計糧頁面預設月份更新」）。後接全形冒號「︰」。
2. **原有問題**：過去實際見到／做到的行為，勿寫程式原因。
3. **改善方法**：而家系統改成怎樣。
4. **具體影響**：用日期、入口、角色等可核對的事實收束（例如「每月 11 號起顯示當月」）。
5. **使用方法**：同事要點邊、揀邊、可否改回。一句完。

長度約 **80–120 字**（標題計入）；短過用戶另訂上限時跟用戶。繁體中文；專業、陳述句；一句接一句，唔分點、唔加 emoji。

**預設**（禁「默示」；禁對使用者寫「默認」除非畫面本身用該詞）。寫畫面用詞（計糧、頁頂、下拉式選單），唔寫檔名、commit、測試、migration、URL 參數。舊行為要準：同事見到「8 月開 7 月」＝當時固定開**上一個曆月**，唔好寫成永遠釘死某一個月，除非真係釘死。唔承諾未上線、未驗證的效果。

**今次計糧（正確）：**

```
計糧頁面預設月份更新︰計糧頁面過去固定顯示上一個曆月，現時系統更新為預設顯示當前日期前十天所屬的月份，即每月 1 至 10 號顯示上月計糧、11 號起顯示當月。用戶可使用頁頂下拉式選單切換月份。
```

```
改咗 defaultPayrollMonthKey，today-10 日，monthOptions[1] 唔再用。
```

## 完成回覆

只交出可複製的公告正文（必要時再加一句「可貼去收件匣／群組」）。唔夾工程細節，除非用戶一併要工程交接。
