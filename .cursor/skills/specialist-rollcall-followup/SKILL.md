# 專科班點名跟進（查庫 → 報告 → WhatsApp）

從 **MainHope_production** 即時查指定日期範圍的專科班（`classes.class_kind = 'group'`）點名情況，交書面報告，再按老師產出可貼訊息。

無 MCP `execute_sql`／無 production 查庫權限：**停、通知使用者**，唔好用舊表或假資料交差。見 `.cursor/rules/no-forced-output-without-access.mdc`。

回覆用**繁體中文書面語**；術語跟 `.cursor/rules/terminology.mdc`。

## 何時用

用戶叫：專科點名檢查、未點名、部分點名、奇怪宣告、出席無宣告、催老師補點、產出 WhatsApp 提醒、某段日期（如 10/1–10/7）專科出席。

## 步驟

1. **日期範圍**：用戶指定用該 `from`–`to`（含首尾）。無指定則問清楚，或預設「今日往前 6 日～今日」（共 7 日），並在回覆寫明範圍。
2. `list_projects` 揀 **MainHope_production**（`gudmbilboyhouotilrvt`；唔好用 staging）。
3. 讀 [queries.md](queries.md)，用 MCP `execute_sql` 跑概覽 → 未點／部分點 → 出席無有效宣告 →（可選）取消堂／void 宣告摘要。
4. **出報告前再跑一次「欠點名明細」**（老師可能已補點；WhatsApp 只根據最新結果）。
5. 按下方口徑分類；交書面報告。
6. 若用戶要提醒／WhatsApp（或步驟內一併要）：按老師產出可貼訊息（見下方模板）。今日**尚未到開始時間**的堂唔好當欠點名催。

可選：把 JSON 快照寫入 `docs/generated/<year>/`（檔名含日期範圍）；**唔 commit** `docs/generated/**`，除非用戶明講要發佈。

## 口徑（必須跟）

對齊 `.cursor/rules/ops-data-check.mdc`，**唔好發明問題**：

| 觀察 | 處理 |
| --- | --- |
| 有排程、有效宣告 0 | **空班**，唔算未點名、唔催老師 |
| 日期完全無 `schedules` 列 | 可能校舍假期（未建列），正常；唔當取消 |
| `status = 取消` | 列取消原因即可；唔當未點名（除非用戶要審取消是否誤標假期） |
| 老師名／班碼含 Test、HWKP | 排除前線完成度 |
| 今日堂、`start_time` 仍未到（用香港時間） | 可列「今日稍後」，**唔入催點訊息** |
| 連堂兩節 | 分開兩列判斷；一節已點唔好當整日未做 |
| 拖欠學費仍上紙 | 正常；唔當宣告錯 |

**專科班**：`class_kind = 'group'`。`academic_year_label` 可能為 null——用日期範圍＋`course_code_full` 前綴（如 `2627-%`）收窄，唔好只靠 label。

**未點名**：未取消、有效宣告 > 0、該 `schedule_id` 出席列 = 0。

**部分點名**：有效宣告 > 0、已有部分出席，但仍有有效宣告學生無出席列。

**出席無有效宣告**：有 `attendance_details`，同堂同生無 `attendance_declarations.status = 'active'`。再查：有無任何宣告列、報讀、`leave_makeup_records`（調堂）、權益消耗。常見成因：調堂目標缺宣告、堂後先報讀、跨班人手點名。

**出席狀態**：白名單見 `src/lib/attendanceBilling.ts`；範圍內若出現非白名單字串才標「異常狀態」。

void 宣告（`enrollment_purged`／退讀等）且**無**殘留出席 → 預期，唔當缺陷。

## 報告結構

先 1–2 句結論（幾堂欠點、有無宣告異常），再分節：

1. **概覽**（按日：排程數／取消／空班／未點名／部分點名）
2. **欠點名明細**（日期、時段、course code、科目、老師、尚欠姓名）
3. **部分點名**
4. **出席無有效宣告**（每人一句解讀：調堂／事後報讀／跨班等）
5. **不當異常**（空班、假期無列、正常取消——一句帶過）
6. **按老師匯總**（過去欠點堂數；今日未開課另計）

## WhatsApp／催點訊息

- **一老師一則**；只含該老師尚欠項目（最新查庫）。
- 標題＋全形冒號「︰」；班別**分列**（日期含星期、時段、科目＋年級、`course_code_full`、尚欠姓名）。
- 書面語、短、可行動（補點／與前台核對）；唔寫 SQL、migration、agent、權益池。
- 名冊異常（出席無宣告）另開一則或同一則末段「另：…請與前台確認」，唔好同催點名混成技術報告。
- 無欠項的老師唔產訊息。

### 催點名模板

```
專科班點名提醒︰

系統顯示以下課堂的點名紙仍有學生、尚未完成點名，請盡快於系統補點︰

1. YYYY-MM-DD（星期X）HH:MM–HH:MM　<科目>（<年級>）<course_code_full>
　尚欠：<姓名、姓名>

完成後請於點名紙核對狀態是否已全部選取。謝謝。
```

部分點名把首句改為「以下課堂為部分點名，點名紙尚有學生未點」，並列已點／尚欠。

### 名冊核對模板（可選）

```
專科班出席核對︰

系統顯示 YYYY-MM-DD（星期X）HH:MM–HH:MM　<科目>（<年級>）<course_code_full>
已點「<姓名>：<狀態>」，但當日點名紙無名／與報讀班別不符。請確認當日是否確有該生上課；若否，請告知行政以便更正。謝謝。
```

年級由 course code 推（`…1001…`→中一 … `…6001…`→中六）；推唔定則只寫科目＋ code。

## 勿做

- 唔好把空班、假期無列、正常取消當缺陷催老師。
- 唔好在缺查庫權限時用腳本／舊 snapshot 充當今日報告。
- 唔好自動改庫（補宣告、改出席）——除非用戶另開寫入任務並明確授權。
- 唔好 commit `docs/generated/**`。
